## 二、黄色：有状态变更但不产生大额资金流出

| 动作 | 级别 | 判据 | 强验证 |
|---|---|---|---|
| `transfer.create` 转账 | 黄 ≤1000 / 红 >1000 | 赛题原文「小额转账（日累计≤1000）黄色，超过则红色」 | 黄=计划卡确认；红=见第三节 |
| `transfer.schedule` 定时转账 | 同上 | 立即扣款，口径同 `transfer.create` | 同上 |
| `transfer.book` 登记未来转账 | 黄 | `ActionKind.STATE` → `amount_applies=False`，登记时不扣款 | 计划卡确认 + 明示「到期自动扣款」 |
| `card.lock` 锁卡 | 黄 | 可逆状态变更，只加严 | 计划卡确认 |
| `card.apply_virtual` 申请虚拟卡 | 黄 | 赛题原文列在黄色；`daily_limit_cents` 是额度不是流出 | 计划卡确认 + 明示额度 |
| `subscription.cancel` 取消订阅 | 黄 | 赛题原文「订阅取消」黄色；未来流出转负 | 计划卡确认 + 明示「取消后不可恢复原价」 |
| `funds.freeze` 冻结预算 | 黄 ≤1000 / 红 >1000 | 视同流出（`kind=OUTFLOW`），按当日累计判档 | 计划卡确认 + 明示冻结额与解冻条件 |
| `funds.release` 解冻 | 黄 | `ActionKind.INFLOW` → 金额档不适用；不产生流出 | 计划卡确认 |
| `wealth.redeem` 理财赎回 | 黄 | `ActionKind.INFLOW` → 金额档不适用；资金回流入账 | 计划卡确认 |

## 三、红色：必须强验证 + 可撤销/补偿

| 动作 | 级别 | 判据 | 强验证 |
|---|---|---|---|
| `transfer.create` / `transfer.schedule`（>1000） | 红 | 日累计 >1000 | 交易密码 + 计划卡 + 逐节点复核 |
| `funds.freeze`（>1000） | 红 | 日累计 >1000 视同流出 | 同上 |
| `wealth.subscribe` 理财申购 | 红（无条件） | 赛题原文「理财申购」红色；`OFFICIAL_RED_ACTIONS` 已含 | 同上 + 风险测评结果出示 |
| `card.unlock` 解卡 | 红（无条件） | 赛题原文「解挂/解卡」红色；`OFFICIAL_RED_ACTIONS` 已含 | 同上（解卡=削弱风控） |
| `card.report_lost` 挂失 | 红（无条件） | `reversible=False`、`ActionKind.IRREVERSIBLE` → 不可逆必红 | 同上 + 明示「不可撤销，需补卡」 |
| `merchant.order` 商户下单 | 红（无条件） | `reversible=False` → 不可逆必红；计划级也因「含不可逆节点」判红 | 同上 + 明示「下单后不可退」 |
| `card.set_limit` 调额 | **红（今晚升）** | 调额=削弱风控，可被用于绕过日累计 1000，属欺诈前置动作 | 交易密码 + 计划卡 + 明示新旧额度 |
| `subscription.sign` 代扣签约 | **红（今晚升）** | 签约即授权未来无感扣款，当次看不到资金流出，欺诈高发路径 | 交易密码 + 计划卡 + 明示周期与下次扣款日 |
| `transfer.request_collection` 发起收款 | **红（今晚升）** | 收款请求可被伪造成「退款/返现」，典型诈骗话术载体 | 交易密码 + 计划卡 + 明示收款对象 |
| `password.change` 修改密码 | **红（今晚新增）** | 赛题原文三级权限明确列「密码修改」为红色 | 旧密码 + 新密码二次输入 + 计划卡；审计只记事件与摘要，不落明文 |

## 四、计划级判据（比单动作更严）

单动作全黄，整条计划仍可能判红。`policy/pdp.py` 的 `evaluate_plan` 现行为：

1. 计划**净效应** ≥ 1000 元 → 红（`NET_EFFECT_THRESHOLD_YUAN`）。
2. 计划**含任意不可逆节点** → 红。
3. 单动作判红 → 整条计划红（取最严）。

**⑥ 生日链路的实际结果**（B 案）：`funds.freeze(1000) → merchant.order(299) → funds.release(701)` 净流出 299 元（应为黄档），但因含 `merchant.order` 不可逆节点，**整条计划判红**，走强验证。答辩时这条要主动讲：不是我们判错，是「不可逆」优先于「金额小」。
