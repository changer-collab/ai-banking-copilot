## 1. 一句话定位

账单看得出问题、卡片管得住动作：账单页把「异常大额 / 异地 / 深夜」连同置信度与免责摊开，可疑项一键跳到卡片管理；卡片页把锁卡 / 挂失 / 补卡 / 调额按三色区分，红色动作灰显并写清强验证路径。

## 7. 技术亮点

1. 7 类判据 + 置信度 + 「不当作已确认」免责：命中只进可疑清单，金额可回读（`txn_id` + `record_id` + `content_hash`）。
2. 时间 / 地点为空跳过判据并说明：`booked_at` / `city` 为 NULL 不参与深夜 / 异地判定，notes 里显式说明，避免把「不适用」当「异常」。
3. 用户画像卡（消费结构 / 订阅负担 / 大额风险）：服务端一次算好，前端只渲染；空账期返回 `top_category=null` 并画空态。
4. 能力边界进后端：导出 Excel / 按城市 / 按时间点 / 退款状态四类问法在场景层明确拒绝，不再拿大额扫描结果冒充答案。

## 8. 边界 / 失败案例

- 样本不足：账期只有 1 笔支出时，不据此确认重复扣费 / 价格变化 / 订阅扣费（notes 明说）。
- 时间城市为空：跳过判据并说明，不猜。
- 调额超上限：50 万直接拒绝并给出上限 5 万，不产生计划卡。
- 失卡补卡失败：已完成的锁卡 / 挂失保留，状态 `partial`，会话可重新发起补卡，不悬空冻结。
- 已知未打通：「把可疑的都锁卡」现在会明确说明「一次只能一张 + 流水未记录卡号，无法从可疑交易反推卡片」（10-28 已修，不再含糊追问）；真·批量锁卡仍依赖「卡号进流水」（跨场景 ⑥）。卡片无法按卡统计当日已用（流水无 card_id）。

## 9. 评委追问 3 题

1. 问：你们的「可疑」是不是 AI 编的？
   答：不是。7 类判据全部是确定性代码，命中即生成带 `txn_id / record_id / content_hash` 的证据；置信度固定（如深夜 55%、异地 60%），页面常驻「识别结果只作核对线索，不当作已确认」。
2. 问：误报了怎么办？
   答：可疑项只提示复核，不自动执行任何动作；用户可在对话里发起锁卡（黄/红卡走确认或强验证），也可忽略；误标不会改账单事实，撤销入口在可疑清单页（后续补一键忽略）。
3. 问：为什么挂失/调额要点两次？
   答：这两个是红色动作（不可逆 / 削弱风控）。面板上灰显并写明路径，用户在对话里确认计划卡后还要过一次服务端强验证（演示码），执行回执带审计 ID，记录页可查。
