## 3. PPT 第 6 页（统稿口径）

## 8. 技术亮点

1. **等级由服务端评分算出，模型不能自填**：`score_to_profile()` 按 5 题得分占比映射 R1–R5，问卷文案明写「等级不能自填」；前端只展示结果，不参与算分。守卫测试：`tests/scenarios/test_wealth_assessment.py`。
2. **适当性先拒后问 + 被拒给替代**：`web/session.py` 的 `_precheck_wealth()` 在原话里带出等级 / 产品时先做适当性判定，不通过直接 `blocked`，不再让用户白补金额；拒绝文案由 `scenarios/wealth.py::suitability_refusal()`（:168）生成，并附本人等级下可申购清单。只作用于 `wealth.subscribe`，赎回不做适当性判定。守卫测试：`tests/web/test_wealth_closure.py`。
3. **轻量知识图谱只解释、不改判**：`scenarios/wealth_graph.json`（17 节点 / 16 边）+ `scenarios/wealth_graph.py`（`load_graph()` 带 `lru_cache`），产品卡可展开「为什么推荐 / 为什么不能买」并给出路径；能不能买仍由 `product_catalog()` 的 `eligible` / `reason` 决定，图只读它。费率无数据就写「未知」。守卫测试：`tests/scenarios/test_wealth_graph.py`（含「与 `gateway/seed.py` 逐字段一致」「全部解释不含收益承诺词」）。
4. **能力边界整句拒绝，不拿假前提继续办事**：`web/session.py` 的 `_balance_tamper_refusal()` 命中「余额 / 存款 + 篡改动词 + 理财动作词」三条件时整句 `blocked`，不生成任何申购卡——「把余额改成 100 万再去买理财」不会变成一张 100 万的申购单。这类拒绝走 `capability_boundary=True`，与「策略拒绝」分开计数，不会把会话推到熔断。守卫测试：`tests/web/test_wealth_closure.py` 两条（命中即拒 / 不带理财动作时不套话术）。

## 9. 一条真实边界（如实写，不写「暂无」）

**赎回能做，但金额不能超过当前持仓；而「当前持仓」之外的收益，本演示给不出。**

- 界面与网关同口径：持仓卡赎回输入框上限就是该产品持仓（今日截图里是「最多 3000.00」），服务端 `core_bank.py:878-881` 再判一次，超额直接 `InsufficientHoldingError`，不会出现「赎回成功但持仓变负」。
- 收益恒为「未知」：演示环境没有净值数据，`HOLDING_INCOME_UNKNOWN`（`scenarios/wealth.py:321`）直接下发「未知（演示环境无净值数据，不推算盈亏）」，前端不补 0、不按份额 × 净值倒推。
- 未测评 / 不匹配一律 fail-closed：没有有效测评时产品全部灰显、只给「先完成测评」的解锁路径；R4 在当前 R3 下输入框与按钮都 `disabled`，不会「点了才报错」。
- 其余已知缺口（不改、只留证）：页面暂无独立「理财产品选择器」，浏览器里只说「买 1000 元」仍会得到「安全拒绝：未知意图」（该路径由 API 与单测覆盖，截图 `docs/2026-10-28/截图/徐思云/closure/S6-2b-bare-amount.png`）；持仓渠道列全为「—」，因为 `holdings_payload()` 目前不返回 channel，前端走空值分支不编造。

## 10. 评委追问 3 题

1. 问：风险等级是不是模型给的？会不会被提示词操控？
   答：不是。等级由服务端 `score_to_profile()` 按 5 题得分占比算出，模型和前端都拿不到写等级的入口；没有有效测评时全部产品灰显，先拒后问，操控提示词最多让意图理解跑偏，改不了等级判据。

2. 问：拒绝了用户，体验岂不是很差？用户接下来能做什么？
   答：拒绝卡同时给两样东西——本人等级下的可申购清单（如 R3 的均衡配置 B，起购 5000.00 元）和解锁路径（上方「重新测评」重答）；但前端不承诺重测后一定能买，等级仍由服务端算分，避免诱导。

3. 问：这个知识图谱是不是为了演示硬加的？会不会编数字？
   答：只做本场景的只读解释图：17 节点 / 16 边全部来自内置演示数据，9 条单测守卫「与 seed 逐字段一致」「费率是未知不是编造」「解释里不含收益承诺词」；能不能买仍由服务端 `eligible` 判定，图不改判、不生成任何数字。
