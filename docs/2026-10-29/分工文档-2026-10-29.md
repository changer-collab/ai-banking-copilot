## 3. 全员统一规范

### 3.1 三样素材（每人只补这三样）

| 项 | 要求 | 交到哪 |
|---|---|---|
| 一句真实原话 | 正常 / 缺信息 / 该拒绝，各一句最好；必须是自己场景真跑出来的 | `docs/2026-10-29/答辩素材/{姓名}.md` |
| 一条真实边界 | 做不到什么，如实写；不写「暂无」 | 同上 |
| 一张新截图 | 1440×1000，10-29 之后的新壳；场景页有数据那张优先 | `docs/2026-10-29/答辩素材/截图/{姓名}/` |

- **不改版式**：页序、配色、字号、页脚一律以组长成品为准。
- **不新增页**：确有必须补的内容，写进自己素材 md，由组长决定是否进备注。
- **数字必须能复跑**：写不出复跑命令的数字不要写进材料。

### 3.2 实测问题修复（编号制）

收到编号后按这个格式回，缺一项视为未交付：

```text
编号：TRF-03
改了什么：______（文件 / 函数，一句话）
为什么改：______（现象，不说术语）
复测步骤：______（首页 → X → Y，或一条命令）
```

- 只改本条，不顺手重构、不改别人场景。
- P0 当天修；P1 24 小时内；P2 10-30 晚统一收口。
- 修完必须自己复测一次，贴复测结果；不接受「应该好了」。

### 3.3 截图与版本链

- 统一 `1440×1000 @2x`，真 PNG；不要 JPEG 改后缀、手机长图、零散小裁片。
- 命名 `scene-<场景英文>-<state>.png`：`transfer / bills / wealth / cards / subscriptions / life` × `entry / data / empty / loading / error`。
- 场景三态图放 `docs/2026-10-28/截图/{姓名}/`；答辩用图放 `docs/2026-10-29/答辩素材/截图/{姓名}/`。
