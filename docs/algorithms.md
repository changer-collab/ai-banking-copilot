# 核心算法说明 · AI 银行副驾

> 覆盖官方必交文档之二：**核心算法说明**。安全裁决、事实读取和执行门均为确定性逻辑；真实模型只负责受约束的意图提案与独立审查，模型结果不直接执行。

## 1. 三色权限分级（PDP）

- 主干：**绿色 = 自动执行且仅纯查询**；**黄色 = 用户确认**（`日累计 ≤ 1000 元`）；
  **红色 = 强验证**（`日累计 > 1000 元`、不可逆、挂失）。
- 增强层：`MANUAL` 人工接管 · `DENY` 拒绝并解释。
- 合成：`L_final = max(base, 各 modifier)`，冲突取更严（fail-safe），原因并集（可解释）。
- 对象态机：`blocked` 为**吸收态** ⇒ `DENY`（唯一可压制金额维度者）；对象维度**只升档不降档**。
- 多候选收款人：**不产出级别**，强制澄清。

## 2. 冻结哈希与执行门

- `cfhash(nodes)`：计划节点集合（含锚点与控制槽参数）的确定性 SHA-256（键排序 + 紧凑分隔符）。
- **计划级**：`assert_frozen(plan, frozen_hash)` 校验 `cfhash(plan.nodes) == frozen_hash`（防 TOCTOU）。
- **节点级**：`manifest_hash(call)` 对每次工具调用算 `cfhash` 并复核，二者叠加即「节点 ∈ 已冻结确认子图」。

## 3. 计划级净效应（NE）

带符号资金流（以流出为正）：
`转账 / 定时转账 / 理财申购 / 代扣签约 / 冻结 = +流出`；`理财赎回 / 解冻 = −流出`；
`订阅取消 = −未来流出`；`挂失 = 不可逆，不入 cf，单列触发 ≥ 红`；`查询 / 状态变更 = 0`。
阈值判据：`NE ≥ T_net ⇒ 计划级 ≥ 红`；`NE = 0 ⇒ 计划级 ≤ 黄`。

## 4. 意图锚点与深度约束

`explicit`（用户明说）/ `user_approved`（计划卡批准）深度 0；`derived`（机械推导）**父必须深度 0**、
**深度 ≤ 1**、**禁止 `derived → derived`**。锚点授予权归交互层，LLM 只能提议、不能授予。

## 5. 控制槽补全（确定性）

取值优先级：受信任调用方选定对象 → 确定性解析器（名册匹配 / 金额解析 / 时间解析）；都不行则追问。
铁律：`unverified` 永不进控制槽（类型层 `Slot(CONTROL, Value(UNTRUSTED))` 直接抛错）；
备注等文本只入数据槽，**永不被解释为指令**。

## 5.1 受约束语义帧（真实模型通道）

真实模型不再被要求直接输出可执行动作、对象 ID 或授权结论，而是先输出
`SemanticFrame(domain, operation, mode, evidence, roles)`。服务端只接受可回指用户原文的
连续 `evidence`，并通过白名单把 `(domain, operation, mode)` 映射到已有动作目录；收款人、
账户、卡片、产品和订阅 ID 仍只能由事实网关与用户显式选择产生。

金额按角色隔离：`transfer_amount`、`investment_amount`、`budget_limit`、`order_amount`、
`daily_limit` 不可互相填充。例如“生日预算 800 元”只能生成预算/排期约束，不能自动生成
800 元花束订单；只有用户明确给出“订 299 元鲜花”时，299 元才可作为订单金额。低置信度、
重叠写帧、缺少必填角色或证据不连续时，系统只追问或转人工，不猜测执行。

## 6. 算子白名单与受限沙箱

派生数字（求和 / 均值 / 占比 / 同比 / 环比）只能经**封闭白名单**算子计算，且每个输入必须携带
`record_id`（出处强制）；分母为 0 拒绝计算。派生运算在**受限子进程沙箱**执行：
无网络、禁库（`sqlite3` 等）、禁写文件、限时——**沙箱不得回写事实网关**。

## 7. 审计链、熔断与撤销

- 审计链：追加式 JSONL + HMAC 哈希链（`entry_hash` 链接前一环）；旧 SHA 链须显式迁移；篡改或非法行 → 校验为假。
  范围声明：只证过程合规 + 可追溯，**不证决策正确**（签名来自 TCB）。
- 熔断：五类触发（连续授权失败 / 注入命中 / 高频高风险 / 策略连续拒绝 / 会话异常），
  **只加严不降级**，唯一降级出口是显式解锁。
- 撤销：窗口内且未结算 → 直接撤销；已结算 → 走 saga 补偿并**如实告知**（"本期已扣、已发起退回"），
  **不得谎称"已取消"**。

## 8. 评测算法（序关系不变式）

- `I1′ 金额`：`日累计 < 1000 ∧ 无异常 ⇒ ≤黄`；`> 1000 ⇒ ≥红`（节点级）。
- `I2′ 对象`：`blocked ⇒ 拒`。
- `I3′ 可逆性`：`不可逆 ⇒ ≥红`。
- `I4′ 净效应`：`NE ≥ 阈值 ⇒ 计划级 ≥红`；`NE = 0 ⇒ 计划级 ≤黄`（限货币型 DAG）。
- 绿色纯度：任何绿色节点必须是纯查询。
- 全局非退化：各级别各 ≥1；某不变式恒真即判无效。must-pass 外部锚必须全数通过。

## 9. 执行一致性与证据指标

- 同一 `execution_id` 的确认重试返回原回执且业务快照、交易数和 `write_receipts` 不增加；相同内容的新提交必须生成新执行 ID 和独立业务效果；旧卡或哈希不符必须 409 且无业务写入。
- `web-smoke-v2` 按合法、攻击、同执行幂等和独立提交分组计算分子/分母；`evidence-dev-v1` 与 `heldout-v1` 由数据文件和 manifest 决定分母，不从通过结果反推。
- 每个数值同时核对展示值、单位、公式和来源记录；结果保存 code/data/prompt/scorer hash 与逐例业务终态。模板结果和真实模型结果使用不同 `channel`，严格通道失败不能由模板补齐。

## 10. Planner 与独立 Reviewer

Planner 只产出 `IntentProposal`，经可信补槽和场景构造形成实际 `Plan`；Reviewer 在 `Session._after_outcome` 审查同一份 Plan，报告绑定执行 ID、冻结哈希和提示词版本。Reviewer 只能要求澄清、拒绝或转人工，不能改写动作、金额、对象或授权；最终级别仍由规则风险官 `assess_plan` / PDP 决定。

## 11. 生活链路参数化装配（L1–L7）

生活场景不可枚举，但**链路的形状**可枚举。做法是把「说一句话」先归一化成三个维度的取值，再映射到有限个链路原型，最后用参数填满原型——**不新增动作、不新增安全语义**。

### 11.1 三维度归一化

| 维度 | 取值 | 判据（确定性，非模型自由生成） |
|---|---|---|
| A 时间形态 | A1 一次性 · A2 先备后花 · A3 周期 · A4 到日必达 | 有无「提前」→ A2；有无「每/每月」→ A3；有无「到某日必须」→ A4；否则 A1 |
| B 资金形态 | B1 户内锁 · B2 单次流出 · B3 周期流出 · B4 流入 · B5 户内搬 | 资金是否离开账户 → B1 锁 / B2 出 / B4 入；是否反复 → B3；是否仅换仓 → B5 |
| C 风险形态 | C1 卡风险 · C2 身份风险 · C3 授权范围 · C4 无风险 | 涉卡操作 → C1；涉密码/挂失 → C2；涉额度或签约 → C3；纯查询 → C4 |

三维度取值只决定**骨架**，具体的人、金额、日期、商户全部落到参数槽，仍走 §5 的控制槽补全（`unverified` 不入槽，缺则追问）。

### 11.2 原型表（骨架 → 动作序列）

| 原型 | 骨架（A·B·C） | 动作序列（全部取自当前注册表的 28 个动作） |
|---|---|---|
| L1 预算锁定 | A2 · B1→B2→B1 | `funds.freeze(预算)` → `merchant.order(≤预算)` → `funds.release(差额)` |
| L2 定期出资 | A3 · B3 · C3 | `subscription.sign` / `transfer.schedule` → 到期扣款 → `subscription.list` 可查可停 |
| L3 出行保障 | A4 · C1 | `card.set_limit` / `card.lock` → 期间消费 → 到日 `card.unlock` |
| L4 大额凑集 | A4 · B5→B2 | `account.balance` → `wealth.redeem`（补缺口）→ `transfer.create` |
| L5 失卡止损 | A1 · C1+C2 | `card.lock` → `card.report_lost` → `card.apply_virtual` → `password.change` |
| L6 阶段盘点 | A1 · C4→B3 | `bills.yearly` / `category_trend` → `subscription.cancel` → `wealth.subscribe` |
| L7 分摊收款 | A1 · B4 | `transfer.request_collection` → `account.transactions`（确认到账）→ `bills.monthly`（记账） |

**参数化**：同一原型换 5 个参数即成新场景——`触发事件`（生日 / 搬家 / 开学 / 过年）、`预算金额`、`到期日或提前量`、`商户与标的`、`收款对象`。以 L1 为例：`birthday:{user_id}:{year}` 换成 `moving:{user_id}:{year}`，动作序列、三色判定、审计字段一字不改。

### 11.3 组合律（原型串联）

原型可串成更长的 DAG，串联不改变任何单节点的裁决逻辑，只改变计划级净效应 NE：

- `L6 → L4`：年终盘点发现缺口 → 赎回凑钱还房贷（`NE` 累加后可能计划级升红）。
- `L5 → L3`：卡丢了补新卡 → 立刻给新卡设出行限额。
- `L1 → L7`：生日聚餐先锁预算 → 群里 AA 收款回补。

串联的两条硬约束：① **净效应跨原型累加**（§3），不得因拆分到两个原型而绕过阈值；② **依赖必须显式成边**，前序节点未成功则后继节点不得执行，失败按 §7 走 saga 释放冻结。

### 11.4 装配不变量

1. **不新增动作**：原型只能编排既有白名单动作；需要新语义时先走 `docs/plans/README.md` 冻结面裁决。
2. **不新增授权路径**：每个节点仍逐节点过 PDP，计划级再取最严（§1）。
3. **不新增事实来源**：庆祝日、商户回执、余额一律来自事实网关；模型只能产出意图提案。
4. **幂等与补偿**：冻结必须携带确定性 `budget_hold_id`，下单必须携带确定性 `occasion_id`，二者共同保证重放不重复扣款；任何节点失败都要释放冻结（§7）。
5. **可验收**：每条链路必须通过 §8 的四条序关系不变式，并在 `eval/harness.py` 留下「触发 → 追问 → DAG → 计划卡 → 三色 → 审计 → 可恢复」七段证据。

### 11.6 2026-11-02 增量：事实自洽与资金核查

1. **原话与任务图**：`life_event_records` 增 `utterance` / `hold_ref` / `occasion_ref` / `results_json`；卡片展示原话、三节点链路（预留 → 下单 → 释放）与各自状态，一条 record 对应一条 schedule，不再重复渲染。
2. **资金来源确定性核查**（`web/life_funding.py`）：`available` = 活期可用余额；`inflow` = 触发日（含）前到期持仓本金；状态 `ok / later / short / unknown`。只在页面与对话追加提示，不阻塞、不改计划、不改授权。
3. **定时解析**：`merchant.order.order_on` 从原话相对日期解析；解析不出但含时间词 → 追问送达日，不默认今天；未来日期只登记预约。
4. **口径修正**：`funds.freeze` 用户文案改「资金预留」；理财到期日按「起息日 + 产品期限」确定，删除「推算 / 非官方公告」措辞；兑付以银行回单为准（演示不接真实清算）。
