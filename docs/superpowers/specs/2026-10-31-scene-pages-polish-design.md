## 0. 一条关键事实（决定了后面所有口径）

对话里的写操作**已经**写进账本，账单页看不到只是账期口径问题：

| 写动作 | 是否写 `transactions` | 位置 |
|---|---|---|
| `transfer.create` | 是（category=转账，direction=out） | `gateway/core_bank.py:174-188` |
| 转账冲正 | 是 | `gateway/core_bank.py:394` |
| 理财申购 / 赎回 | 是 | `gateway/core_bank.py:903`（`_wealth_flow`） |
| 订阅取消 / 卡状态变更 | 否（不产生资金动作，属正确行为） | — |

而 `/api/bills/analysis` 的默认账期是「**上一个完整月**」（`web/app.py:1105`），演示时钟为 `2026-10-01`，所以永远落在 `2026-09`。

⇒ 「对话操作不影响账单」= 写入发生在 10 月、页面永远看 9 月。**修账期即可，不需要新增账本写入。**

## 1. 演示时钟与数据口径（全局）

### 1.1 时钟推进

`gateway/core_bank.py` 的 `DEFAULT_BOOKING_DATE` 由 `2026-10-01` 改为 `2026-10-31`。

连带必须同步（否则演示数据出现"过去日期"）：

| 项 | 现值 | 改为 |
|---|---|---|
| `_SUBSCRIBUTIONS` 下次扣款 | `sub_video 2026-10-08`、`sub_music 2026-10-15` | `2026-11-08`、`2026-11-15` |
| 二级用户订阅 | `sub_b_video 2026-10-12` | `2026-11-12` |
| `merchant_store` 生日常量 | 「生日前 2 天落在 2026-10-01」 | 改为落在 2026-10-31（文案与常量同步） |
| 预约转账种子（若有未来日期） | 按新基准日复核 | 顺移到 11 月 |
| `scenarios/scheduling.REFERENCE_DATE` | 引用 `DEFAULT_BOOKING_DATE` | 自动跟随，无需改 |

**硬约束**：种子与测试里**不允许出现晚于基准日**的"已发生"流水。10 月流水按 1–31 日铺满，最后一条不晚于 10-31。

### 1.2 种子扩到 10 月

`gateway/seed.py`：

- `_SEED_LAST` 由 `(2026, 9)` 改为 `(2026, 10)`；
- 10 月按现有「每月 15 条」结构生成（8 条固定 + 7 条生活开支），`_YEAR_SCALE` 不变；
- 二级用户 `_SECONDARY_LAST` 同步改为 `(2026, 10)`；
- 覆盖区间变成 `2025-01 .. 2026-10 = 22 个月`，流水总数由 315 变为 330 —— `tests/gateway/test_seed.py` 里的**等号计数断言**（`== 315`、`== 5`）要逐条改成新值或改为下限（沿用仓库既有"计数断言用下限"的裁决，改用 `>= 330`）。

### 1.3 账单默认账期改为「当月」

`web/app.py:1105-1107` 的默认账期由 `today.replace(day=1) - 1 天`（上月）改为：

- 默认 `year/month = deps.today` 的当月；
- 返回体新增 `period_basis`（`"current_month"` / `"explicit"`）与 `data_through`（该账期数据截止日，= 当月最后一天与今天取小）；
- 页头文案：「账期 2026-10 · 截至 10-31 · 演示数据」。

这样 10 月 31 日的转账（对话里刚办的那笔）落在默认账期里，刷新账单页立刻可见。

**注意**：`scenarios/bills.py` 的 `_period` 兜底仍保留"上一个完整月"，只改 API 层默认值，不动场景层语义。

## 2. 账单页（`#/scene/bills`）

### 2.1 账期切换器

页头加一行 segmented 控件：

```
[ 本月 2026-10（完整） ] [ 上月 2026-09 ] [ 选月份 ▾ ]
```

- 「本月」显示当月与截至日；若当月有当天新写入的流水，标签带角标「含今日新增 N 笔」；
- 选月份沿用现有 `?year=&month=`；
- 切换后调用 `/api/bills/analysis?year=&month=`，不整页重载。

### 2.2 结论卡精简（截图：内容太多）

现状 ~9 行 + 三层 `details`，且「重点核对」与「识别线索」数据重复。

新结构（首屏 ≤5 行）：

| 区块 | 内容 |
|---|---|
| 结论行 | `narrative.summary`（后端已生成、前端目前未用）作为一句话结论；拿不到时回退 `billVerdict()` |
| 指标行 | 本期支出 / 笔数 / 待核对 **3 个数字** |
| 重点核对 | 最多 **2 条**，每条一行：名称 + 金额 + 状态 chip |
| 折叠区 | 一个 `<details>`：「展开完整分析」内含：消费画像、两张图、完整清单、数据来源与局限 |

去掉「重点核对」与「识别线索」的重复渲染（同一份 `findings` 只出现一次）。

## 3. 转账页（`#/scene/transfer`）

### 3.1 收款人选择器

现状：一个自由文本框，用户敲全名，靠后端全名/尾号匹配（`planning/slots.py:375-388`）。

改为**可搜索选择器**：

- 输入即过滤候选，候选来自两处真实事实：
  - 名册：`gateway.payees_of(user_id)`（姓名、账号尾号、手机尾号后四位）
  - 最近转账：`/api/transfers` 的去重收款人
- 候选行显示：`李娜 · 账号尾号 9021 · 手机 1234`
- 无匹配时显示「按此姓名继续」，提交后仍走服务端澄清（**不猜**）
- 新增**只读**接口 `GET /api/payees`（只读名册，不新增业务动作、不改策略）

### 3.2 金额与备注

- 金额下方加 3 个快捷值（100 / 500 / 1000），点击填入
- 加「备注」输入框（选填），提交时拼进话术 `转给李娜 500 元，备注：房租`（服务端已有 `extract_remark`）
- 成功后清空表单并保留收款人（便于连转）

## 4. 理财页（`#/scene/wealth`）

### 4.1 产品大类（持仓占比按大类）

产品元数据加 `category`（场景层字段，不动 `contracts/`）：

| product_id | name | category |
|---|---|---|
| `wp_cash` | 活期理财篮子 | 货币类 |
| `wp_bond` | 稳利债券 A | 债券类 |
| `wp_mix` | 均衡配置 B | 混合类 |
| `wp_equity` | 成长精选 C | 权益类 |

- `/api/wealth/overview` 的 `products[]` 与 `holdings[]` 都带 `category`；
- 持仓占比环形图**按大类聚合**，产品明细移到下方列表；
- 图例：`货币类 12.5% / 债券类 75% / 混合类 —`，产品级明细在列表里。

### 4.2 净值曲线（模拟数据，明确标注）

新增 `wealth_nav` 表（`gateway/store.py`，schema v7）：

```sql
CREATE TABLE IF NOT EXISTS wealth_nav (
    product_id TEXT NOT NULL REFERENCES wealth_products(product_id),
    on_date    TEXT NOT NULL,
    nav_bp     INTEGER NOT NULL,   -- 净值 × 10000
    PRIMARY KEY (product_id, on_date)
);
```

- 种子按**确定性公式**生成近 90 天序列：`nav = 10000 + yield_bp * days_since_start / 365 + 固定振幅 × sin(day)`（零随机、可复现）；
- `FactGateway` 新增 `wealth_nav_of(product_id, days)`；
- `/api/wealth/overview` 给每个持仓返回 `nav_series[{on_date, nav}]`、`nav_start`、`nav_now`、`income_cents`（按买入日净值算**参考收益**）；
- 前端用**内联 SVG 折线**画（项目不引第三方图表库），图右上角固定标注「模拟净值 · 演示数据」；
- 产品目录卡片也带上迷你曲线（同一份 `nav_series`）。

### 4.3 推荐理由补指标

产品卡与推荐理由里加入真实数字：年化收益率（`yield_bp`）、期限（`term_days`）、起购（`min_amount`）、费率（`fee`），理由文案由 `scenarios/wealth_graph.explain_product` 引用这些字段生成，不再只说"风险等级匹配"。

## 8. 影响面与风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 演示时钟推进 105 处引用 | `DEFAULT_BOOKING_DATE` 被大量引用；其中多数是 `import` 常量而非字面量，自动跟随 | 逐条核 44 处硬编码 `2026-10-01`；改完必须跑全量 `pytest` |
| 种子计数断言 | `test_seed.py` 有 `== 315` 等号断言 | 按仓库既有裁决改为下限 `>= 330` |
| 订阅"已逾期"观感 | 时钟推进后 10-08/10-15 变成过去 | 种子顺移到 11 月 |
| 净值是模拟数据 | 仓库红线禁止宣称未实现能力 | 图上与接口字段都标 `simulated: true`，页面写「模拟净值 · 演示数据」 |
| 账单默认账期变更 | 影响"上月账单"类用例与文档口径 | 只改 API 默认值，场景层 `_period` 语义不动；文档同步 |
| 新增 `/api/payees` | `web/app.py` 属"先申请再改" | 走变更申请卡 |
