# 转账页真实数据与安全建模设计（2026-11-02）

## 1. 背景与诊断

### 1.1 现场问题

截图中的转账页只有「收款人姓名 + 金额 + 备注」三个输入，付款账户、收款账号、开户行、转账方式、手续费、到账时效、撤销能力、反诈提示全部缺失。页面文案还残留 `/api/options.quota`、`计划卡`、`红色动作`、`前端不计算` 等工程术语，用户无法据此完成一笔真实转账。

### 1.2 记录页“不像真实数据”的根因

`GET /api/transfers` 的数据本身来自 `transactions` 表，但存在两处失真：

1. **收款人解析错误**：种子流水 `merchant = "转给李娜"` 被当成 `payee_id = "李娜"` 去名册里查，查不到就回落为「收款人已隐藏」。用户看到的是“隐藏”，实际只是解析失败。
2. **字段缺失**：接口只返回金额、日期、状态、账户名，没有渠道、收款账号、转账方式、手续费、用途、附言。记录页只能显示“金额 + 日期”，看起来像演示占位。

此外，演示库中的种子历史与演示过程中真实执行的转账混在一起，界面没有区分，进一步削弱可信度。

### 1.3 设计目标

- 让转账页具备真实转账的最小业务闭环：**从哪个账户出 → 转给谁（姓名 + 账号 + 开户行）→ 怎么转（实时 / 普通 / 次日）→ 多少钱 → 什么用途 → 如何确认**。
- 让记录页成为可对账的流水：每笔都能看到收款人（脱敏）、收款账号尾号、方式、手续费、状态、用途/附言、渠道，并能“再转一笔”。
- AI 对话与页内表单使用同一套事实和同一套执行链路，不出现“页面一套、对话一套”。
- 严格遵守项目诚实性红线：演示能力必须标注，不宣称未实现的人脸 / 短信 / 真实清算。

### 1.4 非目标

- 不接入真实支付清算、真实短信、真实人行账户核验。
- 不新增第 26 个业务动作；继续复用 `transfer.create` / `transfer.schedule` / `transfer.book`。
- 不保存完整收款卡号；演示环境只保存后四位用于核对。
- 不修改 `policy/gate` 判据、`policy/pep` 三条硬约束、审计哈希算法。

## 2. 数据事实模型

### 2.1 收款人名册 `payees`

新增可空列 `bank_name TEXT`：

- 已有种子收款人补齐演示开户行；
- 新收款人通过 `POST /api/payees` 登记，只保存姓名、账号后四位、开户行、手机号后四位；
- `identity_confirmed` 对新收款人固定为 `0`（未核验），界面如实显示“未完成账户核验”。

### 2.2 转账流水 `transactions`

新增可空列，全部由服务端写入，前端只读：

| 列 | 含义 |
|---|---|
| `payee_id` | 收款人 id；旧种子为空 |
| `transfer_method` | `realtime` / `normal` / `next_day` / `large` |
| `transfer_fee_cents` | 手续费（分）；演示环境固定 0 |
| `transfer_purpose` | 结构化用途：`rent` / `salary` / `reimburse` / `other` |
| `transfer_remark` | 自由附言 |
| `transfer_status` | `settled` / `processing` / `cancelled` |

旧库通过 `_OPTIONAL_COLUMNS` 幂等迁移；旧流水这些列为 `NULL`，读取层按“历史记录”处理，不猜。

### 2.3 定时 / 延时转账 `scheduled_transfers`

新增 `method`、`purpose`、`fee_cents` 三列（带默认值，幂等 `ALTER TABLE`）。`transfer.book` 写入，登记时不扣款，到期由既有调度链路扣款。

### 2.4 记录接口 `GET /api/transfers`

统一从事实网关读取，返回：

```
kind, record_id, source, payee_id, payee(脱敏), payee_account_tail,
payee_bank, payee_phone_tail4, amount_cents, booked_on, status,
method, method_label, eta_label, fee_cents, purpose, purpose_label,
remark, account, account_tail, channel, can_repeat, can_cancel
```

- `source`: `live`（演示过程中真实执行）/ `seed`（种子历史）；界面用不同标签区分。
- `status`: 即时且已记账 = `已到账`；`booked_on > 业务日` = `处理中`；定时登记 = `已发出申请·可撤销`；已取消 = `已撤销`。
- 收款人解析顺序：`payee_id` 精确命中 → 姓名唯一命中 → 原文姓名（保留脱敏）→ 仅此时显示“收款人未知”。不再把“李娜”解析失败显示成“已隐藏”。

## 3. 转账页结构

页面从上到下：

1. **额度概览**
   - 单笔限额、今日已用、剩余可用、本月累计（演示口径）。
   - 进度条只表达“已用 / 日累计限额”。
   - 限额说明折叠：卡片通道限额可在「卡片」页调整；日累计限额由演示风控规则固定。

2. **付款账户**
   - 下拉选择本人账户，显示账户类型与可用余额。
   - 默认上次使用账户（本地记忆）；金额超过余额时红字提示。

3. **收款人**
   - 姓名：输入 + 名册候选。
   - 收款账号：选择名册时自动带出后四位；新收款人必须填写，演示环境只保存后四位。
   - 开户行：选择名册时自动带出；跨行必填。
   - 手机号：选填，用于到账通知。
   - 命中 `blocked` 收款人时禁止提交，显示“该收款人已停用”。

4. **转账方式**（四选一）
   - 实时到账：7×24 秒到，单笔上限按卡片通道；演示即时记账。
   - 普通到账：预计 2 小时内，演示即时记账并标注。
   - 次日到账：次日 00:00 后发出，**登记不扣款、可撤销**。
   - 大额通道：单笔 5 万以上，工作日处理；演示环境按红色强验证处理。

5. **金额与用途**
   - 金额实时校验：单笔限额、剩余日累计、账户余额、月累计。
   - 超限立即红字说明具体原因，提交按钮禁用。
   - 用途为结构化下拉（房租 / 工资 / 报销 / 其他），附言为自由文本，二者分开。
   - 删除 100 / 500 / 1000 快捷金额。

6. **手续费与到账时间**
   - 明示“手续费 ¥0.00（演示环境免收）”；到账时效按方式显示。
   - 跨行不额外收费，但标注“真实跨行手续费以银行实际为准”。

7. **反诈提示**
   - 首次向新收款人转账：黄色提示条，倒计时 3 秒后才允许提交。
   - 金额 ≥ ¥1,000：显示“大额转账需完成强验证”。
   - 附言命中“安全账户 / 刷单 / 返利 / 验证码 / 屏幕共享”等关键词：红色提示并暂停提交，要求用户确认已知晓。
   - 收款人 `blocked`：直接拦截。

8. **确认与验证**
   - 服务端计划卡汇总：收款人姓名 + 脱敏账号 + 开户行 + 付款账户 + 金额 + 方式 + 到账时间 + 手续费 + 用途。
   - 黄色卡按钮写“确认转账”；红色卡在本页内申请一次性验证码并提交，文案明确“演示验证码，不是真实短信 / 人脸 / 交易密码”。
   - 执行成功后显示“已发出申请”或“已到账”，两者不混用。

## 4. 限额口径

| 维度 | 来源 | 本页行为 |
|---|---|---|
| 单笔限额 | 卡片 `transfer_limit_cents` 与演示通道上限取小 | 金额超过即红字提示 |
| 日累计限额 | 既有 PDP 口径 `min(官方阈值, 客户分档)` | 显示已用 / 剩余；不足时提示“今日剩余不足” |
| 月累计限额 | 演示口径：日累计 × 30，并在界面标注“演示” | 仅做提示与前端拦截，不改变服务端执行授权 |
| 账户余额 | `accounts.balance_cents` | 不足时提示“可用余额不足” |
| 手续费 | 演示环境 0 | 明示“演示免收” |

历史记录中单笔超过当前限额是允许的：限额可能已调整，页面在“限额说明”中写明，不把历史记录判为异常。

## 5. 24 小时延时与撤销

- “次日到账”走 `transfer.book`：登记 `scheduled_transfers`，登记时不扣款。
- 记录页对该笔显示“已发出申请·可撤销”，提供“撤销”按钮，调用既有 `/api/life-schedules/cancel`。
- 撤销成功后记录状态变为“已撤销”，并在详情中保留原申请信息。
- 状态文案严格区分：
  - `已发出申请·可撤销`：钱还没扣；
  - `处理中`：已扣款但未到记账日；
  - `已到账`：已记账。

## 6. AI 对话对齐

1. 新增可选槽位：
   - `transfer_method`：实时 / 普通 / 次日 / 大额；
   - `purpose`：房租 / 工资 / 报销 / 其他。
2. 自然语言解析：
   - “24 小时延时转账”“次日到账” → `transfer.book` + `next_day`；
   - “普通到账”“2 小时后到账” → `transfer.create` + `normal`；
   - “实时到账” → `transfer.create` + `realtime`；
   - “大额转账” → `transfer.create` + `large`。
3. 计划卡摘要新增“转账方式 / 到账时间 / 手续费 / 用途 / 收款账号尾号”。
4. 澄清问题改为“请确认收款人（姓名 + 账号尾号 + 开户行）”，多候选时列出尾号与开户行。
5. 页面“用 AI 助理转账”把已填的账户、收款人、金额、方式、用途带入对话，不空跳；表单为空时按钮文案为“用 AI 助理转账”，不写“这一笔”。
6. 记录页“再转一笔”把收款人、账号、方式、用途、金额带回表单，并可直接在对话生成预填计划卡。

## 7. 记录与明细页

转账记录表头：

`记账日 | 收款人 | 金额 | 方式 | 状态 | 用途 | 记录号 | 详情`

- 收款人单元格显示“李* · 尾号 9021 · 招商银行”。
- 状态用颜色区分“已到账 / 处理中 / 已发出申请·可撤销 / 已撤销”。
- 详情内显示手续费、附言、付款账户、渠道、来源（AI 办理 / 演示历史）。
- 每条记录提供“再转一笔”；定时记录额外提供“撤销”。
- 顶部增加“按收款人汇总”折叠视图，便于对账（P2，随记录页一起落地）。

## 8. 文案清理

删除或替换：

| 原文案 | 新文案 |
|---|---|
| 中文数字、完整手机号、日累计限额 | 从本人账户转出，收款人需核对姓名、账号与开户行 |
| 这里不在前端计算任何数字 | 删除 |
| 先出计划卡 / 红色动作 / 强验证 | 点击确认后进入核对与验证 |
| 数字均读服务端 | 删除 |
| 去对话办这一笔 | 用 AI 助理转账 |
| 收款人已隐藏 | 收款人未知（仅解析不到时使用） |

## 10. 验收标准

- 新转账必须选择付款账户；不选不能提交。
- 收款人必须能核对姓名、账号尾号、开户行；名册命中自动带出，新收款人可填写并登记。
- 转账方式四选一，每种方式显示到账时效与限额。
- 金额超单笔 / 日累计 / 余额任一限制时，提交按钮禁用并给出具体原因。
- 首次向新收款人转账有 3 秒反诈提示；命中可疑话术有红色提示。
- 次日到账登记后不扣款，记录页显示“已发出申请·可撤销”，可撤销。
- 记录页每笔包含方式、手续费、状态、用途/附言、收款账号尾号，并能“再转一笔”。
- 记录页能区分“AI 办理”和“演示历史”，不再出现解析失败导致的“收款人已隐藏”。
- 所有演示能力均有“演示”标注，不宣称真实短信 / 人脸 / 清算。
