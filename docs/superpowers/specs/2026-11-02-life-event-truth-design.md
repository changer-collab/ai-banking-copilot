# 生活事件页「业务真实性 + 数据自洽」设计（2026-11-02）

> 输入：截图问题清单（方案一）+ 赛题视角重构建议（方案二）
> 约束：不新增业务动作（仍 25 个）；不改 `contracts/`、`policy/pep.py` 三条硬约束、`policy/gate.py` 判据；
> **不跑 pytest**（用户明确要求，本轮只用 `ruff` / `mypy` / 手工页面核对）。
> 目标不是「把两份清单全做」，而是**先判定哪些真的必须改、哪些改了反而失真**。

## 0. 结论摘要

截图里的问题可以归成 4 类，优先级从高到低：

| # | 问题 | 性质 | 本轮结论 |
|---|---|---|---|
| 1 | 同一事件在「已登记预约」和「最近记录」各存一份，日期/状态/隐私标记不同步 | 真 bug（展示层） | **改** |
| 2 | 四张 L1 卡片都显示「冻结余额 ¥701.00」 | 真 bug（后端把全局 hold 发给了每张卡） | **改** |
| 3 | 「下周三订花」在 11-01 就「已执行」 | 真 bug（`order_on` 没从原话解析，默认成今天） | **改** |
| 4 | 11-04 要花 ¥1,000，理财 11-30 才到期，页面无告警 | 真缺失（跨场景联动最有价值的能力） | **改** |
| 5 | 日历 11-04 没点、「5 个事件」与点不一致、「原型」标签噪音 | 真 bug（展示层） | **改** |
| 6 | 「冻结」是自造银行业务，法律上不成立 | **判断有误**：赛题⑥明确要求「锁定资金」，`funds.freeze` 是既有 25 动作之一 | **保留机制，改口径与文案** |
| 7 | 理财到期是「推算」，应直接取官方到期日 | **部分成立**：到期日由「起息日（官方）+ 产品期限（官方）」确定性得出，不是猜；错的是措辞 | **改文案，不加冗余字段** |
| 8 | 页面应重构成「任务编排中心」+ 合作商户 + 目标储蓄签约 | 方向对，但部分实现会违反诚实性红线 | **采纳意图还原/任务图，拒绝假商户与假产品** |

一句话：**方案一的业务事实判断大体成立，但「删掉冻结」会丢赛题评分点；方案二的方向成立，但「已接入 3 家合作商户」「对接增利煲存款产品」这类表述在本仓库没有实现，不能写。**

## 1. 两份方案的逐条裁决

### 1.1 方案一（业务真实性）

| 条目 | 裁决 | 理由 / 做法 |
|---|---|---|
| ① 废掉「预算锁定型」 | **不采纳删除，采纳其合规内核** | 官方赛题⑥示例就是「锁定资金并自动完成鲜花、蛋糕预订」；`funds.freeze` 是既有动作，删掉等于删评分点。真正要修的是：用户可见文案改「资金预留」（不再说「冻结储户存款」）、删除「冻结单 <裸 ID>」、明示「确认后才预留，目标完成或终止即释放；演示环境不涉及真实资金」。 |
| ② 理财到期改接官方持仓 | **部分采纳** | 不新增 `WealthHolding.maturity_on`：它与 `purchased_on + term_days` 完全等价，属冗余字段 + 迁移风险。改为把口径说对：**「到期日按产品条款确定（起息日 + 期限）」**，删除「推算 / 非官方到期公告 / 未赎回按今日处理」，并补一句「兑付到账以银行回单为准（演示不接真实清算）」。 |
| ③ 资金来源核查 + 冲突告警 | **采纳（P0）** | 新增确定性核查：事件金额 vs 触发日可用余额 + 触发日前到期返本；不足/资金晚到 → 黄条 + 对话提示。 |
| ④ 定时需求被立即执行 | **采纳（P0）** | 根因：`merchant.order.order_on` 由场景层填充，`_build_l1` 在拿不到时默认 `REFERENCE_DATE`；原话里的「下周三」从未进入 `order_on`。改为从 `span` 解析相对日期；解析不出但有时间词 → 澄清，不静默按今天执行。 |
| ⑤ 同一事件两份记录 | **采纳（P0）** | 存储层本来就是「一条 record + 一条 schedule（`record_id` 关联）」，问题在展示层把两者各画一遍。改为以 record 为主、schedule 折叠进同一条；日历按 `record_id` 去重；隐私标记统一取 record。 |
| ⑥ 日历不完整/自相矛盾 | **采纳（P0）** | 事件点 = 唯一事件 ID；补上预约触发日；「同一天同类只画一个点」与渲染一致；删除「原型」标签与「原型 N 个」计数。 |
| ⑦ 定期出资缺字段 | **部分采纳** | 补收款人（脱敏）、付款账户、执行日、创建时间；「终止」用**已存在**的 `POST /api/transfers/cancel`。不做「修改/暂停」（无对应动作，不放假按钮）；不编「每月 1 日 / 下次 12-01」（`scheduled_transfers` 只有单次 `booked_on`，无周期字段），如实写「本次仅登记下一笔」。 |
| ⑧ 状态机与杂项 | **采纳** | 每张卡只渲染自己的 hold；未执行不显示「已释放」；「到期」改「触发日」；「去对话办这一笔」按场景改为「去对话」。 |

### 1.2 方案二（赛题视角）

| 条目 | 裁决 | 理由 / 做法 |
|---|---|---|
| 页面改名「任务编排中心」 | **不采纳改名，采纳四段结构** | 导航、文档、测试都叫「生活事件」；改名收益低、连带改动大。把四段内容压进卡片：原话 → 任务图 → 关键信息/资金核查 → 状态与操作。 |
| 「冻结」保留 + 目标储蓄签约 | **采纳文案层** | 卡片与对话明示「预留资金专款专用，目标完成/终止即释放，需你逐张确认」。**不写**「对接增利煲存款产品」——本仓库没有该产品。 |
| 合作商户下单（花礼网/元祖/全场配） | **不采纳** | 没有任何商户 API、没有签约。`FLOWER_OFFERS` 源码里写明「不是真实商户签约」。页面继续标「演示商户，不实际配送」。写成「已接入 3 家」违反项目诚实性红线。 |
| 意图还原区 | **采纳（P1）** | `life_event_records` 增 `utterance`，卡片展示原话 + 识别出的日期/金额/隐私约束。 |
| 任务图可视化 + 场景标签 | **采纳（P1）** | `steps` 增 `node_id / depends_on / domain / state`；前端画横向链路，每个节点带场景标签。 |
| 逐张确认卡片 | **已有，不改** | 现有「计划卡 → 逐节点确认 → 强验证」链路已满足。 |
| 状态闭环 / 回滚 | **已有，不改** | `interrupt` / `reverse` / 预约 `retry|cancel` 已存在；本轮只补「阻塞原因」字段，不做新的回滚机制。 |
| 对话事件去重 / 关联 | **部分采纳** | 同一会话同事件已 upsert。跨会话语义合并（「这是 11-04 生日的一部分吗」）需要稳定事件键，当前没有，**不做**，避免误合并两条真实事件。 |

## 2. 页面新结构（改完长什么样）

### 2.1 顶部

- 标题「生活事件」，副标题「一句话 → 任务图 → 逐张确认」。
- 状态行：`我的记录 5 条 · 已登记预约 1 条`（删除「原型 7 个」）。
- **资金冲突提示区**（仅有告警时出现）：
  > ⚠ 「我爱人生日惊喜」11-04 要用 ¥1,000，但「稳盈短期 A」11-30 才到期。
  > 可选：提前赎回 / 改到 11-30 之后 / 换资金来源。

### 2.2 日历

- 点：`下单` / `提醒` / `理财到期（按产品条款）` 三类；**同一天同类只画一个点**。
- 事件落点优先级：预约触发日 > 计划日期 > 创建日。
- 计数 `N 个事件` = 本月唯一 `record_id` 数，与点一致。
- 图例改为「同一天同类只画一个点，点开看清单」。

### 2.3 记录卡片（一条事件一张卡）

```
[我爱人生日惊喜]                    [已登记预约]
原话：「我爱人生日那天有笔理财到期，正好赎回给她买礼物」
① 资金预留 ¥1,000 → ② 向商户下单 ¥299 → ③ 释放剩余 ¥701
   [资金预留]          [商户]              [资金预留]
触发日 2026-11-04（周三）· 金额 ¥1,000 · 创建于 11-01 09:39
资金核查 ⚠ 最近到期 11-30，晚于触发日
[打开会话]
```

- 已执行卡片追加订单实体：`商户 鲜花礼品店 · 订单号 ord_xxx · 下单日 11-04`（来源：执行回执，不编）。
- 未执行卡片不显示「冻结余额 / 已释放」。
- 隐私事件显示 `仅本人可见` chip（与 record.visibility 同源）。
- L2 卡片：`收款人 李娜（尾号 6688）· 执行日 11-01 · 本次仅登记下一笔` + 「终止登记」（调用既有撤销接口）。

## 3. 数据与接口

### 3.1 `life_event_records` 增列（幂等迁移）

| 列 | 用途 |
|---|---|
| `utterance TEXT NOT NULL DEFAULT ''` | 意图还原：用户原话 |
| `hold_ref TEXT` | 本事件自己的冻结记录（修「每张卡都 ¥701」） |
| `occasion_ref TEXT` | 本事件自己的下单幂等键（判断是否已下单） |
| `results_json TEXT NOT NULL DEFAULT '[]'` | 执行回执摘要 `[{action,status,record_ids}]`（订单号 / 定期转账 ID） |

### 3.2 `GET /api/life-events`

每条 record 新增：

```json
{
  "utterance": "我爱人生日那天有笔理财到期……",
  "calendar_on": "2026-11-04",
  "schedule": {"schedule_id": "...", "due_on": "2026-11-04", "kind": "order", "notify_on": null},
  "budget": {"hold_id": "life:L1:...", "amount_cents": 100000, "state": "active",
             "steps": {"reserve": true, "order": false, "release": false}},
  "funding": {"status": "late", "trigger_on": "2026-11-04", "amount_cents": 100000,
              "available_cents": 0, "inflow_on": "2026-11-30",
              "message": "该笔资金 11-30 才到期，晚于触发日 11-04"},
  "orders": [{"order_id": "ord_...", "merchant": "鲜花礼品店",
              "amount_cents": 29900, "order_on": "2026-11-04"}]
}
```

- `budget` **只按本条记录的 `hold_ref` 查**，查不到就是 `null`（前端画「尚未预留」，不造 0）。
- `schedules` 仍返回（日历与向后兼容），但前端不再单列一块；`record_id` 为空的孤儿预约单独兜底。
- `maturities` 删除 `basis` 里的「推算，非官方到期公告」，改为 `"按产品条款（起息日 + 期限）确定"`。

### 3.3 资金来源核查（确定性）

新增 `web/life_funding.py`：

```
check(gateway, user_id, *, amount_cents, trigger_on, today) -> FundingCheck
  available = Σ 活期账户可用余额（balance 已扣减在用冻结）
  inflow    = 触发日之前（含）到期的持仓本金之和
  status:
    ok     amount <= available
    later  amount <= available + inflow（有到期返本可覆盖）
    short  amount > available + inflow（含「到期日晚于触发日」这一分支）
    unknown 缺金额或缺日期（不展示）
```

- 计划里已有 `wealth.redeem` 的事件跳过（资金来自自身赎回，不做二次核查）。
- 已执行（`executed`）事件不核查（钱已花）。
- 只做提示，不阻塞、不改计划、不改授权。

### 3.4 对话侧（与页面同源）

1. 提交后若核查为 `later` / `short`，在回复末尾追加一句：
   > 资金提醒：「生日惊喜」11-04 要用 ¥1,000，最近到期的「稳盈短期 A」11-30 才到账；可提前赎回、改期或换资金来源。
2. 到期联动的话术删除「推算 / 非官方公告 / 未赎回按今日处理」，改为「按产品条款到期日」。
3. `merchant.order` 的 L1：原话解析出未来日期 → 走既有「只登记预约」；解析不出但含时间词 → 追问送达日，不再默认今天。
4. 计划卡标签：`funds.freeze` → 「锁定预算（资金预留）」；`merchant.order` → 「向商户下单」；轨迹里的「冻结」→「预留」。

## 4. 明确不做（写进交付说明）

- 不新增业务动作；不新增「目标储蓄」「暂停定期出资」「修改预约」等动作。
- 不加 `WealthHolding.maturity_on`（与既有字段等价）。
- 不接真实商户 / 真实配送 / 真实清算；不出现「合作商户已接入」。
- 不做跨会话事件自动合并。
- 不改页面标题为「任务编排中心」。
- 不跑 pytest。

## 5. 验收口径

- `ruff check .`、`mypy` 通过（本轮唯一可自动执行的门禁）。
- 手工核对 5 个场景：
  1. 「我下周三生日，帮我订一束花，预算 1000 以内」→ 只登记 11-04 预约，记录状态不是「已执行」；
  2. 「我爱人生日那天有笔理财到期，正好赎回给她买礼物」→ 记录与预约只出现一次，卡片显示资金冲突；
  3. 四张 L1 卡片不再显示同一个 ¥701；
  4. 日历 11-04 有点，`N 个事件` 与点数一致；
  5. 「每月给爸妈 2000 元生活费」→ 卡片有收款人/执行日/终止入口。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 改 `order_on` 解析可能让部分 L1 从「直接执行」变成「追问日期」 | 仅对**含时间词且解析失败**的句子追问；无时间词保持原行为 |
| 旧库没有新列 | `PRAGMA table_info` 判断后 `ALTER TABLE`，幂等 |
| 执行回执未回写（到期确认走另一会话） | 有回执就展示订单，没有就只显示计划参数，不编单号 |
| 文案改动影响既有测试断言 | 同步更新测试断言；本轮不执行 pytest |
