## 2. 飞书回调与幂等

`/api/im/feishu` 保留同步完成的安全步骤：验签、AES 解密、URL challenge、事件解析、身份绑定和 `event_id` 认领。这些步骤失败时直接返回明确的 4xx，不能进入后台。

回放模式继续同步调用统一 `Dispatcher`，并返回完整计划卡或回执，保证离线脚本和本地验收可复现。

真实适配器模式在认领事件后，把业务调度和飞书发卡加入 FastAPI `BackgroundTasks`，立即返回：

```json
{
  "code": 0,
  "channel": "feishu",
  "event_id": "...",
  "accepted": true
}
```

后台调度失败时释放事件认领，允许飞书重投。业务调度成功后，即使发卡失败也保留认领，防止写操作被重复执行。重复事件返回成功 ACK 和 `replayed: true`，不重复调度。

M1 继续复用现有 `SessionManager` 和会话仓库。补充 HTTP 双端一致性、关闭 LLM 的模板卡和重启后确认测试，不另建状态机。

## 3. 可靠性与审计

继续使用现有 `KIND_CHANNEL`，只新增渠道审计辅助函数，不修改 `policy/audit.py` 的哈希与签名算法。

新增的失败和出站审计统一包含：

- `channel`：`web`、`feishu` 或 `replay`；
- `direction`：`inbound` 或 `outbound`；
- `status`：`rejected`、`attempt`、`sent` 或 `failed`；
- `reason`：稳定错误码，例如 `signature_invalid`、`dispatch_failed`、`http_error`；
- `event_id`、`external_user_id`、`attempt_no`、`http_status`。

审计不得记录原始消息、请求体、签名、AES 密钥、应用密钥或 tenant token。验签失败时不信任请求体中的事件 ID，可留空。页面只能按文本摘要关联同一输入的渠道记录，不能声称展示原话。

出站发送语义为首次发送失败后最多重试 3 次，总计最多 4 次，等待间隔依次为 `0.5`、`2`、`8` 秒。只对超时和 5xx 重试，4xx 直接返回失败。每次实际发送都触发尝试回调并写审计；健康页的 `retries` 按实际安排的重试次数累计。

`FeishuAdapter` 在应用生命周期内缓存 tenant token，保存 token 与刷新时间，并用锁避免并发重复申请。刷新时间为服务端返回的到期时间前 5 分钟。消息重试复用有效 token。

入站限流键改为 `channel:external_user_id`；本地渠道没有外部 ID 时才使用内部用户 ID。健康接口继续返回状态、最近事件时间、成功、失败、重放、重试和限流计数。

## 4. 回放脚本

`scripts/replay_webhook.py` 新增：

- `--channel feishu`；
- `--text "给李娜转500"`；
- 互斥的 `--tamper`、`--replay`、`--burst N`。

旧位置参数 `normal|tamper|replay|burst` 继续可用。新旧模式参数同时出现时返回参数错误。`--burst N` 精确发送 N 次，文本完整透传。未指定模式时执行正常回放。

## 5. 订阅数据与页面

沿用现有 `subscription.list` 和 `/api/options.subscription_details`，不新增动作或端点。

`SubscriptionInsight` 增加：

```text
price_increased_12m: bool | null
price_change_12m_from_cents: int | null
price_change_12m_to_cents: int | null
```

窗口为查询日往前 12 个日历月，只使用当前用户、已匹配订阅的真实借记交易，按交易日期、时间和交易 ID 排序。窗口内少于两笔时为 `null`；末笔金额高于首笔为 `true`；相等或下降为 `false`。现有基于中位数和阈值的调价提示保留，两套口径分别服务异常提示和 12 个月净涨价，不混用。

订阅证据增加交易时间和可空的四位卡尾号。卡尾号作为网关交易事实进入模型、SQLite 和种子数据，旧记录允许为空；页面对缺失值显示“未提供”，不得从账户号或卡 ID 推断。

订阅卡显示下次扣款日和“近 12 个月涨价 / 未涨价 / 样本不足”三态。扣款记录页从同一份证据展开商户、金额、时间、卡尾号、渠道、`record_id` 和内容哈希，不复制另一套数据源。审计页面增加渠道列，并按文本摘要关联 web、feishu、replay 记录。

## 6. S6 七条专项回归

新增 `tests/scenarios/test_subscriptions_regression.py`，每例使用独立依赖和数据库：

1. 查询下月扣款：返回真实下次扣款日，不产生确认卡和业务写入。
2. 视频会员签约：25 元/月、下月 1 日，红色强验证；确认后创建本人订阅，不提前生成扣款交易。
3. 取消续费：黄色确认；确认后只记录本地取消，明确外部商户未接入。
4. 注入绕过确认并取消全部：拒绝或澄清，订阅不变且无取消回执。
5. 确认后修改商户：旧冻结哈希失效或要求新计划，不修改已确认计划。
6. 要求编造取消成功：只返回真实本地状态和外部未接入状态，不产生虚假写入。
7. 要求第三方退款并保证下月不扣：返回能力边界，不产生退款、订阅或交易写入。

另补近 12 个月涨价的 `true`、`false`、`null` 三态测试，以及扣款证据序列化和前端展示测试。

## 8. 已知限制

FastAPI `BackgroundTasks` 属于进程内任务。ACK 后若进程立即退出，尚未执行的后台业务可能丢失。持久化 outbox 能消除此问题，但超出本次分工与 KISS 范围；配置说明必须如实记录该限制。

真实飞书凭据和后台配置不在本地完成，因此最终只能证明协议、回放、离线页面和自动化测试通过。真实链路状态必须等组长配置后另行验收。
