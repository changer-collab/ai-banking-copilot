## 1.6 模型环境怎么配（王昌泽提供，2026-10-27）

> 大家本地都要能跑起 AI 对话，否则前端没法验。配置只有一步。

1. **位置**：仓库根目录，**和 `.env.example` 放一起**（即 `ai-banking-copilot/.env`）。
2. **内容**（三行，密钥照群里王昌泽那条消息原样复制；**文档里不写密钥**）：

   ```dotenv
   DEEPSEEK_API_KEY=sk-********（群里那条消息里的值）
   AI_BASE_URL=https://api.deepseek.com/chat/completions
   AI_MODEL=deepseek-flash
   ```

3. **注意**：
   - `.env` 已在 `.gitignore` 里（`.env` / `.env.*`，只放行 `.env.example`），**不会被提交，也不要手动提交**。
   - 新建文件时确认文件名就是 `.env`（Windows 资源管理器可能藏扩展名，别存成 `.env.txt`）。
   - 放好后重启服务；如果 AI 一直不回话，先看启动日志里模型通道是 `llm` 还是 `fallback`——**`fallback` 说明没读到 `.env`**，先查路径和文件名，不要改代码。

## 4. 生活链路 L1–L7（尹辰）

### 4.1 归类法：三个维度 → 七条原型

任何一件「要用银行办事的生活事件」，都能拆成三个正交问题：

| 维度 | 问题 | 取值 |
|---|---|---|
| **A 时间形态** | 这笔钱什么时候动？ | A1 一次性（现在） / A2 先备后花（锁一段时间） / A3 周期性（每月） / A4 到某天必须完成 |
| **B 资金形态** | 钱怎么动？ | B1 锁在户内不流出 / B2 单次流出 / B3 周期流出 / B4 流入（收钱） / B5 户内搬（赎回→转出） |
| **C 风险形态** | 有什么风险要防？ | C1 卡片风险 / C2 身份风险 / C3 授权范围 / C4 无风险（纯查询） |

A × B × C 组合无穷，但**链路骨架只有 7 种**。新增生活事件时不要新写链路，只问「它属于哪条原型，参数是什么」。

> 答辩要讲的一句话：**我们不枚举场景，我们枚举链路的形状。**

### 5.0 所有人共用的前端规矩（先看这条，再看自己那节）

> **先纠正一个理解**：不是每个人都要另造一个系统。所谓「这个场景要有前端」，指的是**用户在 AI 对话里说到这个场景时，AI 返回的东西在页面上看得清、点得动、查得到**。拆成四条，缺一条就算没做完。

1. **呈现**：AI 的答案要有对应形态，不能一坨纯文本。计划卡 / 确认卡 / 风险提示条 / 明细表，按场景选；**图表是可选项**——觉得加上更清楚就加（账单、收益、预算、进度类通常适合趋势线、占比环、进度条），不加也必须有一张读得懂的卡片或明细表。

3. **执行与策略门**：三色定级口径稳定、红动作强验证不可绕过、注入 / 越权一律降级；
4. **审计与可回溯**：每个动作 / 每个数字都能追到来源（`money_trace` 类指标保持满分）；
5. **失败与降级路径**：模型不可用、下游抖动、渠道断网时「如实说明 + 无副作用」。

**本轮新增（前端已提，后端归这一摊）：登录与身份 + 个人中心**

> 前端两处已经留好口子：**网页侧栏左下角头像**、**APP「我的」顶部头像**，点开都是**个人中心页**。但个人中心背后要的是**后端的登录与身份**，不是一张静态卡片——这块归这一摊（尹辰）。

| 项 | 内容 |
|---|---|
| 解决什么问题 | 现在页面里的 `user_id` 是写死的 demo 用户，前端传谁就是谁。要做「个人中心」就必须有**真正的登录与身份**：谁登录、会话绑到谁、退出登录后旧会话失效。否则「转账给谁 / 查谁的账单」在多人使用时就是串号，属安全硬伤。 |
| 后端改什么 | ① **登录换身份**：登录成功后签发会话凭证，服务端把 `user_id` **从凭证里解出**，不再信任前端传的用户名；② **断言绑定 `user_id`**：`SessionManager` 取会话、计划卡确认、审计落库一律以服务端 `user_id` 为准（`channel` 亦然）；③ **退出登录使会话失效**：退出后旧凭证 / 旧会话不可再用，重新进入要重新登录；④ **敏感操作再验一次**：转账（黄/红）等动作在确认环节做一次二次校验，不靠「上一次登录过」；⑤ 个人中心需要的数据：登录方式、`user_id` / `channel` 绑定、最近登录时间。 |
| 前端改什么 | 个人中心页（网页 + APP）：头像 → 弹出个人中心，展示与身份相关的信息（注意：**前端不改 `user_id` 的安全语义**，只负责展示后端返回的结果 + 触发登录 / 退出）；未登录态给「去登录」，已登录态给「退出登录」。 |
| 验收 | ① 用两个不同身份分别登录，各自看到的会话 / 账户不串；② 退出登录后旧会话（计划卡确认等）**不可再用**；③ 敏感操作在确认时确实再验一次（断点处能看到二次校验）；④ 前端个人中心展示的 `user_id` / `channel` 与后端审计里落的一致。 |
| 依赖 | 无（可先于 D2 的 agent 改善做；与 §5.1 渠道的 `identity` 契约同源，落地前跟王昌泽对一下口径）。 |

> **落地顺序建议**：先做「登录换 `user_id` + 断言绑定」，再做「退出失效」，最后补「敏感操作二次验证」——每一步都能单独验收，别攒成一大块最后一起测。
