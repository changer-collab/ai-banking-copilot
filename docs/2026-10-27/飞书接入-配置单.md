## 一、组长执行的真实飞书配置

### 0.1 四个凭据从哪来（2026-10-29 补）

四个值**不是飞书自动发给你的**，前两个来自应用，后两个由我们自己设定。步骤如下：

1. 打开 <https://open.feishu.cn/app>，用能创建应用的账号登录（个人版飞书也行；企业版首次创建可能要管理员开通开发者权限）。
2. 「创建企业自建应用」→ 填名称「AI 银行副驾」→ 创建。
3. 进入应用 →「凭证与基础信息」：
   - **App ID**：形如 `cli_xxxxxxxxxxxxxxxx`，直接复制；
   - **App Secret**：点「显示」后复制。
4. 「开发配置 → 事件与回调 → 加密策略」：
   - **Verification Token**：点「重置」生成，或自己填一串随机字符串；
   - **Encrypt Key**：同样点「重置」生成，或自己填 32 位随机字符串；
   - 加密方式选「**加密**」；这两个值必须与服务器 `.env` 完全一致。
5. 「添加应用能力」→ 开启**机器人**；「权限管理」至少加：
   - `im:message`（接收消息）
   - `im:message:send_as_bot`（以机器人身份发消息）
6. 「事件与回调 → 事件配置」：请求地址填 `https://<当天隧道域名>/api/im/feishu`，订阅
   `im.message.receive_v1`（收消息）与 `card.action.trigger`（卡片按钮回调）。
7. 「版本管理与发布」→ 创建版本并发布，可用范围至少包含你自己。

> **顺序很重要**：先完成下面第 2、3 步（写 `.env` 并重建 api），确认 health 已是 `adapter`，**再回飞书后台保存请求地址**。
> 否则飞书保存时的 `challenge` 校验会走到验签分支，直接 401。
>
> 如果王昌泽已经建过应用，直接找他要 App ID / App Secret，并确认他还记得当时设定的
> Verification Token / Encrypt Key；不要重复创建第二个应用。

### 5. 绑定真实 open_id（仓库暂无 HTTP 入口）

`channel_identities` 是 fail-closed 的唯一放行依据（`web/app.py:1535-1549`），未绑定直接 401 `identity_unbound`。
前端只展示「渠道绑定 N 个」计数，**没有发码 / 绑定的后端接口**，只能手工写库。

取 open_id：给机器人发一条消息，在飞书后台「事件订阅 → 调试台」的原始报文里看 `event.sender.sender_id.open_id`。

```bash
docker exec aib-api-1 python -c "import sqlite3;c=sqlite3.connect('/app/runtime/copilot.db');c.execute(\"INSERT INTO channel_identities VALUES ('feishu','ou_你的open_id','u_demo','2026-10-29T00:00:00+00:00')\");c.commit();print(c.execute('select * from channel_identities').fetchall())"
```

`bound_at` 用 ISO8601（现网那条是 `2026-10-28T15:40:31.866850+00:00` 这个格式）。

### 7. 域名风险

trycloudflare 快速隧道域名不固定：`aib-tunnel` **一旦重启，回调地址立即失效**，飞书后台要同步改。
日常更新只重建 api（`up -d --build api`），不动 `aib-tunnel`，地址就不会变。

### 8. 回滚

删掉 `.env` 与 `docker-compose.yml` 里的四行 → 按第 3 步重建 → 回到 `mode=replay`，接口行为与现在一致。

## 二、消息入口与身份前置

POST /api/im/feishu 先校验时间戳、nonce、签名，再解密和解析事件；URL 校验返回 challenge。事件进入业务前必须已有 channel=feishu 的外部身份绑定，未绑定直接返回 401 identity_unbound，不执行计划、不写资金事实。当前代码提供身份目录的签发/消费能力，具体绑定码发放与兑换流程需由组长按部署方式接入或预置；不能把未实现的 Web 自助绑定流程写成已完成能力。

## 三、立即 ACK、回放与出站重试

- 真实 adapter 模式：入口验签、解析、幂等认领和身份检查后立即返回 code=0/accepted=true；业务调度和飞书卡片发送放入 FastAPI BackgroundTasks。
- replay 模式：本地回放走同步 dispatch，返回完整计划卡/回执，便于验收脚本核对 record_id 和 replayed。
- 出站发送只对超时异常与 HTTP 5xx 重试，最多 3 次重试（总尝试次数最多 4 次），退避为 0.5s / 2s / 8s；4xx 不重试。
- 已知风险：BackgroundTasks 依赖当前进程存活。进程在后台任务执行前退出时，任务可能丢失；生产部署需由组长配置进程存活、日志和失败补偿策略，本文不宣称已有可靠队列。

## 四、本地四种回放

服务端使用确定性模板启动：

~~~powershell
$env:AIB_DISABLE_LLM = "1"
.\.venv\Scripts\python.exe -m ai_banking_copilot
~~~

旧位置参数接口（兼容）：

~~~powershell
.\.venv\Scripts\python.exe scripts\replay_webhook.py normal
.\.venv\Scripts\python.exe scripts\replay_webhook.py tamper
.\.venv\Scripts\python.exe scripts\replay_webhook.py replay
.\.venv\Scripts\python.exe scripts\replay_webhook.py burst
~~~

新开关接口：

~~~powershell
.\.venv\Scripts\python.exe scripts\replay_webhook.py --channel feishu --text "查一下余额"
.\.venv\Scripts\python.exe scripts\replay_webhook.py --channel feishu --text "查一下余额" --tamper
.\.venv\Scripts\python.exe scripts\replay_webhook.py --channel feishu --text "查一下余额" --replay
.\.venv\Scripts\python.exe scripts\replay_webhook.py --channel feishu --text "查一下余额" --burst 30
~~~

预期口径：normal 返回计划卡或回执；tamper 返回 401；replay 第二次返回 replayed=true 且业务只执行一次；burst 触发入口限流，超过 20 条/分钟的请求返回 429 与 Retry-After: 60。本地回放不代表真实飞书已部署。

首次使用全新本地运行库时，需先预置回放身份绑定；否则返回 401 `identity_unbound` 是正确行为：

~~~sql
INSERT OR IGNORE INTO channel_identities(channel, external_user_id, user_id, bound_at)
VALUES ('feishu', 'ou-replay', 'u_demo', CURRENT_TIMESTAMP);
~~~

真实部署时把 `ou-replay` 换成实际飞书 `open_id`，并绑定到对应内部 `user_id`；不要把未绑定外部身份直接映射到演示用户。
