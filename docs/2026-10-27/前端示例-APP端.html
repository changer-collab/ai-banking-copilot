APP 端施工要点（照这 12 条做）

与网页端示例同一套约定，只是窄屏；与分工文档 §5.0 一一对应。

  1. 手机端形态 = 可安装 PWA：主仓库没有原生 App / 小程序；窄屏断点 + standalone manifest 就是「App 端」，与网页端共用一套后端与状态机。
  2. 底部 Tab 四格：首页（场景列表）/ 对话 / 记录 / 我的。对话是独立 Tab，场景与对话分开两屏。
  3. 场景页 = 功能页：首页是场景列表，点进去是该场景的原生功能（额度 / 收款人 / 产品 / 卡片 / 持仓…）。这一屏不放聊天。
  4. 对话页 = 独立一屏：会话切换（含「新建」）+ 消息流 + 输入框；不和场景功能杂糅在一起。
  5. 对话空态照参考图：居中 AI 图标 + 「从一句话开始」+ 说明 + 一排预设快捷消息 + 三色口径小字。
  6. 预设快捷消息（网页 / APP 都要有）：3–5 条贴近真实业务的句子，点一下直接发出去，别写「示例 1 / 测试」。
  7. 计划卡：先给我看、再执行。步骤 + 余额轨迹 + card_id + frozen_hash + 确认按钮；红级走强验证。
  8. 五种气泡形态：用户 / 机器人文字 / 追问卡 / 提示条（黄红）/ 回执。缺参数出追问卡，别让用户再打一句。
  9. 渠道口径：渠道 = 飞书（微信可弃）直接连后端；App 里只有「我的 → 渠道健康」一页，不做渠道聊天页。
  10. 红动作 + 头像：红动作有显式入口，可灰显但要写清「为什么不能点、点哪解锁」，触控目标 ≥ 44px；「我的」顶部放头像，点击弹出个人中心（身份 / 登录与安全 / 通知 / 退出登录），依赖后端登录，属 §5.5 尹辰这一摊。
  11. 可查 + 三态：AI 说做过的操作页面上必须查得到（列表 + 详情 + 状态 + 审计，记录表带「渠道」列）；空 / 加载 / 失败三态齐，失败写人话。
  12. 不造结论 + 零外链：等级、余额、卡状态、登录状态一律读后端；不引 CDN / 外链字体，静态壳沿用现库版本（aib-static-shell-v11）。
