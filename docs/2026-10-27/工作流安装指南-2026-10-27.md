# 工作流安装指南 · 组员版（2026-10-27）

> 一句话：**这不是插件，不用安装**。拉最新代码、用 Trae 打开仓库根目录、开会话时说一句「场景 + 工位」，工作流就生效了。

---

## 1. 它是什么

仓库里已经放好两个文件，Trae 会自动读取：

| 文件 | 作用 | 生效方式 |
|---|---|---|
| `.trae/rules/project_rules.md` | 常驻硬约束：先声明工位、文件权限、先写测试、收工标准、诚实性红线、数字口径 | 每次对话**自动注入**，不需要触发 |
| `.trae/skills/scene-workflow/SKILL.md` | 八工位 S0–S7 展开：每步做什么、产出什么、出口标准 | 提到「场景 / 工位 / scene-workflow」时**自动加载** |

它和 [分工文档-2026-10-26.md](../2026-10-26/分工文档-2026-10-26.md) 的关系：分工文档是人读的规则，这两个文件是 agent 读的同一套规则。**两边改了要同步**，同步由组长负责。

---

## 2. 三步装好（约 5 分钟）

### 第 1 步：拉最新代码

```bash
git checkout sprint/1026
git pull
```

> 工作流文件随分支走。**在旧分支或没 pull 的人，用的是旧规则。**

### 第 2 步：用 Trae 打开**仓库根目录**

打开 `ai-banking-copilot/` 这一层（能看到 `.trae/`、`AGENTS.md`、`src/`）。

- ✅ 正确：`.../ai-banking-copilot`
- ❌ 错误：`.../ai-banking`（父目录，`.trae/` 扫不到）

### 第 3 步：新开一个对话，发开场句

```
场景：① / 工位：S1。按 scene-workflow 走。
```

把「①」换成你的场景（①转账 ②账单 ③理财 ④卡片 ⑤订阅 ⑥跨场景），把「S1」换成你今天要做的工位。

## 3. 自检：怎么知道装好了

发完开场句后，看 agent 的第一行：

| 现象 | 结论 | 怎么办 |
|---|---|---|
| 第一行出现 `场景：① / 工位：S1`，并说「只读不改，先给现状地图」 | ✅ 生效 | 继续 |
| 直接开始改文件、不声明工位 | ❌ 规则没加载 | 检查是否打开仓库根目录、是否拉了 `sprint/1026` |
| 说找不到 scene-workflow 技能 | ⚠️ 技能没加载 | 补一句「读 `.trae/skills/scene-workflow/SKILL.md` 后按它执行」 |
| 一上来就要改 `tools/catalog.py`、`policy/` | ❌ 越权 | 喊停，让对方先出「变更申请卡」（5 行） |

## 4. 每天怎么用

**只发一句开场 + 一句本工位任务**，不要一次给多个工位。

| 工位 | 追加这一句 |
|---|---|
| S0 场景卡 | 「把赛题表里我这个场景那一行的典型能力示例逐条抄下来，标已有 / 半有 / 没有。」 |
| S1 现状地图 | 「只读不改。输出相关文件、已有动作、已有测试、缺口清单。」 |
| S2 话术 | 「给 20 条真人说法候选（口语、省略、错别字、反问），我来挑 12 条。」 |
| S3 门卫 | 「列出本场景全部动作，对照 `docs/2026-10-26/三色基准表-2026-10-26.md`，指出哪些分级不一致。」 |
| S4 后端 | 「先写 D6 七条考题（应当失败），我确认后再实现；实现后贴完整测试输出。」 |
| S5 前端 | 「补齐结果卡 / 确认卡 / 强验证卡 / 失败卡；检查刷新、中断、恢复、接管。」 |
| S6 成绩单（D0 段） | 「只定四个口径 + 出七条考题，不跑分。」 |
| S6 成绩单（D3 段） | 「跑出四个数字，逐条列输入 → 期望 → 实际 → 是否通过。」 |
| S7 材料 | 「出 1 页 PPT 内容（生活话一句 + 技术注解两行 + 一个数字）、30 秒录屏脚本、3 个问答。」 |

**收工必须贴两样**：全量测试输出 + 变更摘要（改了什么 / 为什么 / 动了哪些共享文件 / 需要谁配合）。只回「已完成」不算交付。

---

## 5. 三条红线

1. **一次只做一个工位**。禁止「帮我把整个场景完善一下」——这是最容易把别人的模块改坏的一句话。
2. **共享文件先申请**。`tools/catalog.py`、`policy/**`、`planning/kernel.py`、`.trae/**` 冲刺期仅组长可改；要改先发 5 行申请卡（改什么 / 为什么 / 影响谁 / 怎么回滚 / 要不要结对）。
3. **不许为了变绿放宽断言**。测试红了先定位，不许删对抗样例、不许绕 PDP。

## 6. 常见问题

**Q：我换了分支 / 拉不到最新规则？**
A：`git checkout sprint/1026 && git pull`，然后**新开对话**（旧对话里已注入的规则不会自动更新）。

**Q：我在用 Cursor / Claude Code / 其他工具？**
A：`.trae/` 是 Trae 专用目录，别的工具不会自动读。直接让 agent 先读 `AGENTS.md` 和 `.trae/skills/scene-workflow/SKILL.md`，规则一样适用。

**Q：能不能自己改 `.trae/` 里的规则？**
A：不能。改规则会同时影响 5 个人的 agent 行为。需要改就发申请卡，组长统一改、统一提交。

**Q：规则里写「24 个动作」，代码其实是 25 个？**
A：说明你本地是旧版本，`git pull` 即可（本轮已同步为 25）。

**Q：agent 不听话，还在批量改文件？**
A：直接把 `.trae/rules/project_rules.md` 第 1、2 节贴给它，并明确「本轮只做 Sx，其他一律不动」。仍不改就换新对话重发开场句。

## 7. 组长维护流程

1. 只由组长改 `.trae/**`，改完在群里说「工作流已更新，请 `git pull` 并新开对话」。
2. 规则变更同步三处：`.trae/rules/project_rules.md`、`.trae/skills/scene-workflow/SKILL.md`、`docs/2026-10-26/分工文档-2026-10-26.md`。
3. 数字口径变更（动作数、用例数、路由数）必须同时更新 `docs/RESULTS.md`。
