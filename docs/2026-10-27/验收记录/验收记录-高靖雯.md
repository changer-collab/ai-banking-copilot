### 1.1 换一条降级通道，同一批话术会怎样

`AIB_DISABLE_LLM=1`（没有 Key / 模型不可用时的兜底）下，**同一批 12 条**（2026-10-27 修复后复测）：

- **5 条出卡**：第 1、2（`转账…2026-10-05`，模板按普通转账排期）、8、9、12（`RED`）；
- **3 条追问**：第 3、4 条只追问收款人（金额已接受），第 5 条追问收款人 + 金额；
- **3 条 `blocked`**：第 6、7、11 条（分别缺收款对象 / 错别字 / 无法识别）；
- **1 条误判**：第 10 条「我昨天转给张强那 800 到了吗」被当成转账 → `YELLOW` 计划卡（**未确认即不扣款**，但这是「问句被当指令」，见 §5 缺陷 6）。

修复前是「1 条出卡 / 1 条追问 / 10 条 `blocked`」，现在口语动词（给X转 / 给X打 / 转<数字>）都能接住。

**结论**：模板通道仍是**能力子集**（不做真实模型那套多意图与语义判别），但常用口语说法已不再一律「没听懂」。对外只能说「无模型时降级为模板通道，覆盖部分说法」。两条通道都**没有**误扣款、没有瞎猜对象。

## 5. 已知缺陷与残留（不粉饰）

1. **金额必须带单位**（**已修 · 2026-10-27**）：「转 200 给他」「转 1000 给李娜」「再转 500」都被判成缺金额（追问文案甚至写着「必须带单位」）。12 条话术里 3 条中招。
   已放宽为「**无歧义裸数字**直接当金额」，并保留三条边界：位数 ≤ 4、不是名册卡号 / 手机尾号、不是日期（`2026-10-01` / `10 月 1 日`）或序数（`第 3 笔`）；读不准一律继续追问。
   放宽面只限转账族三个动作（`transfer.create / schedule / book`）；冻结 / 额度 / 代扣签约仍要求带单位；万级无单位（「转给李娜 一万」）依旧不猜单位、先追问。
   回归：`tests/gateway/test_resolvers.py`、`tests/planning/test_slots.py`、`tests/scenarios/test_transfer_nl.py`；评测集新增 `transfer-bare-amount`（黄），原 `transfer-missing-unit` 改为万级样本（仍拒）。
2. **「我昨天转给张强那 800 到了吗」答非所问**：落到账户查询，返回「≥5000 元大额支出（2026-09-01~2026-09-30）」。不在本次改动文件内（属账户 / 账单查询），已报组长。
3. **模板通道覆盖太窄**（**已修 · 2026-10-27**）：原来只认「转给 / 转账 / 汇款 / 打款」，「给李娜转 200 元」0 命中 → 无模型时 `blocked`。
   已补「口语转账」模板：`给X转 / 给X打 / 转<数字>`（可带「请 / 麻烦 / 帮我」前缀），并让转账模板**不再抢**「转账记录 / 流水 / 明细 / 账单」这类查询与「每月给」定期出资。回归：`tests/planning/test_llm_template.py`。
4. **同名澄清卡拿不到候选信息**（**已修 · 2026-10-27**）：原 `ClarificationAsk` 只有 `slot` + `prompt`，卡上只有一个空输入框，用户得自己去翻账号尾号。
   现在每条澄清可带 `candidates`（`label` 给人看 / `value` 回填提交），同名收款人直接给出下拉：`王伟 · 手机尾号 3301 · 账号尾号 8812 · 暂无转账记录`。
   - 标签里的信息全部来自名册 + 已记账流水（最近一次转账日期取 `category=转账 / direction=out` 的流水；定时登记未执行**不算**，写「暂无转账记录」）。
   - **没有**渲染 `138****3721`：名册只存手机后四位（`Payee.phone_tail`），补全中间位就是生成事实（违反 H1），所以如实写「手机尾号 3301」。
   - 回填值用 `payee_id` 而不是自由文本：`_invalid_selection` 只认本人事实列表里的对象 ID，手打「王伟 8812」会被当越权选择拒绝。
   回归：`tests/web/test_clarify_candidates.py`（4 条：有候选 / 无候选不给猜测 / 点选后出卡 / 真转一笔后显示最近一次转账日期）。
5. **多意图补槽会绕圈**：`web/session.py` 的 `_multi_intent_span_questions` 在多意图下反复要求「补充信息」。已报组长。
6. **反问句在模板通道会被当成转账指令**（真实模型通道这次判成了查询）。真实通道有重复转账风险，已报组长。
7. **1000 元整的双口径**（节点档黄 / 计划级红）需要写进口径表，避免验收时被当成 bug。
8. **页面与接口对「账户」槽的口径不一致**（**已修 · 2026-10-27**）：页面上第一句「转给李娜 500 元」会先追问「请选择要操作的账户」；而直接调 `/api/submit` 不带 `selected` 时**静默按储蓄账户**出卡。实测三种提交：

   | 提交方式 | 修复前 | 修复后 |
   |---|---|---|
   | 不带 `selected` | 直接出卡（`awaiting_confirm`） | 直接出卡 |
   | `selected.account = null`（页面就是这么发的） | 追问 `account` | 直接出卡（与不传等价） |
   | `selected.account = "acc_savings"` | 直接出卡 | 直接出卡（显式值仍优先） |

   口径统一为「显式 null = 未指定」：会话层丢弃空值后按受信任默认账户补齐，槽位层也把 `selected[slot] is None` 当未指定。回归：`tests/web/test_submit_selected_none.py`（含「显式账户优先：钱确实从所选账户扣」）。
