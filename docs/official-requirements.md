# 官方要求 → 本项目落点（v2 · 赛题逐条覆盖矩阵）

> **用途**：① 参赛自查的唯一对照表；② 盲审材料（技术文档 / 安全自评）的索引；③ 分工与补口的事实基线。
> **来源**：官方赛题解析《银行 AI 智能体》（国内赛道 · 人工智能）+ 报名规则；代码落点以 `sprint/1026` 当前提交为准。
> **纪律**：只写**代码里能指到位置**的状态；做不到的一律写"半有 / 无"，不写目标态。
> **取代**：v1（2026-10-01）。v1 只有"落点 + 已有"两列，无法回答"到底覆盖到什么程度"。

标记口径：

| 标记 | 含义 |
|---|---|
| **有** | 有独立动作 / 独立入口，能端到端跑通，有测试 |
| **半有** | 有实现但不满足官方点名的那一层语义（如只支持尾号、只判一档阈值） |
| **无** | 未实现 |

## 0. 一页结论

1. **六大场景 25 项点名能力：20 有 / 5 半有 / 0 无。** 半有的 5 项集中在"按手机号转账（仅尾号）""异常交易（仅金额一档）""风险评估（缺问卷入口）""APP/IM 渠道""交互指标未测量"。
2. **三项核心技术要求全部有机制**：权限分级落在 `policy/pdp.py`，五项安全机制各有一个模块，意图规划落在 `planning/` + `scenarios/`。
3. **真正的缺口不在功能，在"可被看见"**：0 份 PPT、0 条视频、0 张结果表。这些只能靠人时补，不能靠写代码补。
4. **今天（10-27）能自己完成的是"文档层"**：覆盖矩阵（本文）、系统架构图（`docs/assets/architecture.svg`）、架构说明、算法说明、安全自评复核。

## 3. 三项核心技术要求

### 3.1 权限分级机制（优先级：高）

| 官方级别 | 官方策略 | 本项目实现 | 落点 |
|---|---|---|---|
| 绿色 | 自动执行（纯查询） | 绿色**只含纯查询**（余额 / 流水 / 账单 / 收益）；意图确认后直接执行 | `contracts/authorization.py` · `policy/pdp.py` |
| 黄色 | 用户确认（日累计 ≤1000、订阅查询取消、虚拟卡申请） | 计划卡展示动作 / 金额 / 依赖 / 余额轨迹，确认**绑定哈希** | `policy/gate.py` · `web/plan_card.py` |
| 红色 | 强验证（>1000、改密、挂失解挂、理财申购） | 一次性挑战 `POST /api/verify/request`，`VERIFICATION_TTL_S=300`，四条件全满足才放行 | `policy/verification.py` · `policy/execution.py` |

**超出官方要求的增强**：计划级净效应（多步合计达阈值即升红）、对象态机吸收态、`MANUAL` 人工接管、`DENY` 拒绝并解释、冲突取最严 + 原因并集。

### 3.2 五项安全机制（优先级：高）

| 官方要求 | 本项目机制 | 落点 | 一句话证据 |
|---|---|---|---|
| 幻觉防护 | **事实零生成**四分法（数值 / 实体 / 语义 / 措辞）+ 出处校验 | `gateway/facts.py` · `web/bill_narrative.py` · `planning/reviewer.py` | 模型无能力编数字：数值只能从网关取，叙事只选结构化 ID |
| 注入防御 | taint + 控制槽结构约束（类型层阻断）+ 执行门哈希成员资格 | `contracts/taint.py` · `planning/slots.py` · `policy/gate.py` | `Slot(CONTROL, Value(UNTRUSTED))` 直接抛错，不靠提示词 |
| 操作审计 | 追加式 JSONL + sha256 哈希链 + 完整决策链路 | `policy/audit.py` · `policy/audit_validation.py` | 篡改或非法行 → 校验为假；每步可追到 `execution_id` |
| 异常熔断 | 五类触发（连续授权失败 / 注入命中 / 高频高风险 / 策略连续拒绝 / 会话异常），**只加严不降级** | `policy/breaker.py` · `policy/breaker_store.py` · `POST /api/operator/breaker-unlock` | 唯一降级出口是显式人工解锁 |
| 沙箱环境 | 白名单算子 + **受限子进程**（无网络 / 禁库 / 禁写文件 / 限时） | `gateway/sandbox.py` · `gateway/sandbox_child.py` · `gateway/operators.py` | 不执行任意 LLM 生成代码；白名单**封闭**，不在名单一律拒绝 |

### 3.3 意图理解与任务规划

| 官方要求 | 本项目实现 | 落点 |
|---|---|---|
| 模糊表达 | 意图提议 + 关键词/别名归一 + 模板降级通道 | `planning/kernel.py` · `planning/llm.py` |
| 省略上下文 | 多轮上下文补全；`session_snapshot` 保留已确认事实 | `web/session.py` · `web/session_snapshot.py` |
| 隐含意图 | 派生锚点（`derived`）**父必须深度 0、深度 ≤1、禁止派生派生** | `planning/anchors.py` |
| 子任务 DAG | `PlanNode.depends_on` 显式依赖；跨场景 = 管道串联 | `contracts/plan.py` · `scenarios/cross.py` |
| 中断 | `POST /api/interrupt`：已执行节点保留，未执行节点作废 | `web/session.py` |
| 回退 | `POST /api/reverse` 撤销窗口 + `policy/saga.py` 补偿；已结算如实告知 | `policy/reversal.py` · `policy/saga.py` |
| 人工接管 | `GET /api/takeover` 转人工包（意图 / 计划 / 命中规则 / 审计 ID） | `web/app.py` |
