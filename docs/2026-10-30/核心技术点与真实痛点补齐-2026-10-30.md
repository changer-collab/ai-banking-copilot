## 0 一页结论

1. 银行真正怕的不是「AI 答错」，而是**AI 做错之后没人说得清、也退不回**。我们的护城河正好在这条链上：事实不可编、动作不可越、执行可回退、回退可举证。
2. 盘点 14 条真实痛点：**10 条已解 / 3 条半解 / 1 条未解**。未解与半解集中在同一处——**节点级执行轨迹与回退过程没有上屏**。能力在后端（`Saga` / `ReversalService` / `_completed_node_ids`），前端只给一句「已回退」。
3. 三个核心技术点定稿：**事实零生成内核 ＋ 计划级净效应裁决 ＋ 三级意图编排**。三者共同的一句话是「**AI 的错误是被拦截的事件，不是被掩盖的事故**」。
4. 本轮只做一件事：把「分层意图 DAG → 冲突串行 → 部分失败 → 冲正回退」这条链**在对话里画出来**，让评委看得见、点得动、追得到。

## 1 银行真实痛点台账（14 条）

判定口径：**已解** = 有实现且有测试/指标；**半解** = 后端有、对外不可见或不完整；**未解** = 无实现。

| # | 真实痛点（银行原话） | 真实银行怎么处理 | 我们现状 | 判定 |
|---|---|---|---|---|
| 1 | 「AI 转错人了，能不能撤回？」 | 转账发起后只能**请求退回**，对方银行同意才退；本地不做删除 | 流出转账走 `ReversalService` 真实冲正（本地记账回补），文案如实说「已按补偿事务退回」 | 已解 |
| 2 | 「撤销不是删记录，是再记一笔反向账」 | 会计上禁止改历史，只允许红冲 | `policy/reversal.py` 逐条冲正，`holds` 只 `UPDATE status='released'`，不改原金额 | 已解 |
| 3 | 「三步只成功了一步，钱悬空了」 | 事务补偿 + 人工对账 | 失败即 `_release_open_holds()` 退回冻结额，状态落 `PARTIAL` 而非 `COMPLETED` | 已解 |
| 4 | 「用户连点两下扣了两次」 | 请求幂等键 | `request_key` + 冻结哈希执行门 + `idempotency` 用例 1/1 | 已解 |
| 5 | 「他没说要转给谁，AI 自己猜了一个」 | 不许猜，必须回问 | 同名收款人/多张卡必澄清，`evidence_dev_v1` 澄清 12/12 | 已解 |
| 6 | 「同名收款人转错了」 | 展示尾号 + 二次确认 | 澄清候选带手机尾号/账号尾号/最近转账日，**只给后四位**不补全 | 已解 |
| 7 | 「确认前不知道会发生什么」 | 交易预览页 | 计划卡「确认后会发生什么」：影响面 / 余额轨迹 / 命中规则 | 已解 |
| 8 | 「事后只看到一句『已完成』」 | 回执 + 流水号 | 回执带 `record_ids` + 审计 ID + 数值溯源面板 | 已解 |
| 9 | 「出了事查不到是谁、在哪一步」 | 不可篡改审计 + 操作留痕 | 哈希链审计、决策链路字段（命中规则/数值出处/授权级别） | 已解 |
| 10 | 「一半成功一半失败，用户看不出哪步成了」 | 分步回执 | 后端有 `_completed_node_ids` / `_pending_node_ids`，**前端只显示「已执行 2/3 步」一句** | **半解** |
| 11 | 「为什么这两步必须排队？能不能同时做？」 | 依赖说明 + 资源锁 | `kernel._wire_dependencies` 同资源串行、异资源并行，依赖进锚点账本，**前端完全不展示** | **半解** |
| 12 | 「回退了哪几笔？剩哪几笔没退？」 | 冲正清单 | `reverse()` 返回 `compensated_steps`，**前端只显示一句话，没有清单与状态** | **半解** |
| 13 | 「本地冲正 ≠ 真实银行退回，别糊弄我」 | 明确区分「已退回 / 已发起退回」 | `subscription.cancel` 已区分本地/商户，**转账冲正未在界面标注「本地冲正」** | **未解** |
| 14 | 「AI 自己说『已为您取消』，其实没取消」 | 外部状态必须透传 | `external_status` 透传 + `CommittedWriteError` 报 `committed_unverified` | 已解 |

**结论**：#10–#13 是同一根链条的四段——**DAG 看不见、依赖看不见、部分失败看不见、冲正边界看不见**。这四段正好是 PPT 第 4/6/7/10 页要演的东西。

> 本表是**改动前基线**。第 3 节 P-1 ~ P-4 落地后，#10–#13 四项转为「已解」（有 HTTP 断言与界面渲染为准）。

## 2 三个核心技术点（定稿）

**① 事实零生成内核 ＋ ② 计划级净效应裁决 ＋ ③ 三级意图编排**

| 技术点 | 技术上是什么 | 别人做不到什么 | 一手指标（`docs/RESULTS.md` §1） |
|---|---|---|---|
| ① 事实零生成内核 | LLM 只出无数字的意图骨架；上屏数值必须来自「算子白名单 × `record_id` 出处 × 回读校验」，派生数字只在受限 DSL 子进程算 | 靠 prompt 说「不要编」拦不住；我们让编造在结构上无处落脚 | 数字可回溯 26/26、74/74 |
| ② 计划级净效应裁决 | 裁决单位是**整张 DAG 的净效应**（对象状态机 + 日累计 + 冻结/结算/释放跨节点合并），不是单动作打分 | 单动作评分遇到「冻结 1000 → 下单 299 → 释放 701」会判错 | 拦截 5/5、31/31；误拒 0/14、0/49 |
| ③ 三级意图编排 | 一级模糊意图识别 → 二级带依赖 DAG（同资源串行、异资源并行）→ 三级冲突消解与部分失败回滚（Saga 逆序补偿 + 中断/回退/接管） | 多数方案只做到「一句话→一次工具调用」，没有部分失败与回退语义 | 一句话完成率 85.71%；澄清 12/12 |

**一句话主线**：别的 Agent 在证明自己聪明，我们在证明自己的错误**变成可拦截、可回退、可举证的会计事件**。

支撑体系（不占核心技术页，但答问必答）：能力令牌思路（执行门哈希 + 冻结哈希 + 一次性挑战）、可回放审计链、Policy-as-Code 规则号。

## 3 本轮要补的四个缺口（P-1 ~ P-4）

| 编号 | 缺口 | 补齐后的对外形态 | 对应痛点 |
|---|---|---|---|
| P-1 | 节点级执行轨迹不可见 | 计划卡下方渲染**任务 DAG**：每个节点带序号、动作中文名、对象与金额、状态（待执行/已执行/已冲正/未执行/挂起/待核验） | #10 |
| P-2 | 依赖与串行不可见 | DAG 的每个节点标注**入边**：`依赖 01 · 串行（同一账户）` 或 `并行（不同资源）`；依赖来自服务端机械推导，前端不猜 | #11 |
| P-3 | 部分失败回滚不可见 | 执行后每个节点显示真实状态；回退后已完成节点转「已冲正」；回退失败时保留「已执行」并明确提示「未宣称已取消」 | #12 |
| P-4 | 冲正边界未标注 | DAG 底部固定一行：**「本地冲正：仅回补本项目模拟核心银行的记账，不等价于真实银行退回」**，与订阅取消的本地/商户口径一致 | #13 |

### 不新增业务动作、不改冻结面

- 不碰 `contracts/`、`policy/gate.py` 判据、`policy/audit.py` 哈希算法、`policy/pep.py` 三条硬约束。
- 只在**已有字段**上做投影：`PlanNode.depends_on`、`_completed_node_ids`、`_unverified_results`、`reverse()` 的 `compensated_steps`。

### 节点状态口径（唯一真源在服务端）

| 状态 | 含义 | 触发条件 |
|---|---|---|
| `pending` | 待执行 | 未执行且会话未终止 |
| `completed` | 已执行 | `node_id ∈ _completed_node_ids` |
| `unverified` | 业务已提交、核验未完成 | `node_id ∈ _unverified_results` |
| `reversed` | 已冲正 | 会话 `REVERSED` 且节点已执行 |
| `suspended` | 已挂起 | 会话 `INTERRUPTED` 且节点未执行 |
| `skipped` | 未执行（流程已终止） | 会话 `FAILED / PARTIAL / BLOCKED` 且节点未执行 |

## 6 门禁与验收

```
ruff check .
mypy
pytest -q
python scripts/e2e_check.py
python scripts/check_served_page.py
```

验收标准：

1. `GET /api/submit` 的 `card.nodes` 含全部节点与 `depends_on`，且**与 `plan.nodes` 逐项一致**；
2. 生日链计划（3 节点）在 DAG 上出现 2 条带标签的依赖边；
3. 执行完成后 `node_progress` 全为 `completed`；
4. 回退后 `node_progress` 全为 `reversed`，且界面显示本地冲正边界；
5. 无新增业务动作、`catalog.py` 不改、`contracts/` 不改。
