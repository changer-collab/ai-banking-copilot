## 二、必须先问清的一件事：官方有没有评测集 / 接口规范？

**查证结论：没有公开的。**

| 查证项 | 结果 |
|---|---|
| 大赛官网赛题页 | 只写"评审期**采用自动评测与专家盲审双轨机制**"，**未附**评测集、接口规范、输出格式或评分细则 |
| 国内 AI 赛道作品提交要求 | 公开渠道**查不到**提交物格式说明。对比：**数据分析赛道**明确写了"赛题五需额外提交预测结果 CSV"、报名走"课堂派"平台——**AI 赛道没有这类公开说明** |
| 国际赛道 | 说明"共用同一套**核心能力标准与评分维度**"，但标准本身未公开 |
| 往届是否有评测集 | **未检索到**任何自动评分数据集或评分脚本的痕迹；往届决赛均为现场答辩 + 黑客松 |

**判断**："自动评测"极可能是**主办方内部的脚本或流程**，不对外公开。

**行动项（10.28 答疑必须问，逐条照问）**：

1. 自动评测是**对提交的代码仓库**跑，还是对**线上部署的服务**跑？有没有接口规范或调用样例？
2. 评测是否要求**固定入口**（如某个 HTTP 端点 / 命令行 / Docker 镜像）？有无约定输入输出格式？
3. 是否提供**公开评测集或样例集**？评分维度与权重是否公开？
4. 评测环境如何提供**模拟银行数据**？是我们自带数据，还是官方给沙箱数据？
5. 六场景中，自动评测覆盖哪几个？"至少 3 个"如何验证？
6. 48 小时黑客松的**题目形式**：是在现有作品上优化，还是现场给新题？
7. 提交物清单的**合规硬项**（作品简介字数、视频时长、文档格式）以哪个页面为准？
8. **是否考察知识库 / 文档问答（RAG）**？官方三项核心技术要求里没有它、六大场景也都是操作类；若盲审或自动评测含"政策 / 条款 / 产品说明问答"用例，需提前知道口径。**答复前不投入 RAG**（理由见第五节 τ-Knowledge 行与第七节总原则"不铺新功能"）。

> 若答不出（或仍是官方内部流程），则按"**无官方评测集**"准备：我们自己造评测集并公开，把"可复现"作为替代证据。

### 3.2 六个共同特点（核心结论）

**① 选题都落在金融"深水区"，不做通用助手。**
量化策略编译、投资决策、记账画像、肿瘤诊断联邦学习——每个都是**一个明确的金融专业问题**，产出**可度量**（策略能回测、诊断有准确率）。没有一个作品是"我做了个大模型助手"。
→ **启示**："银行 AI 智能体"是**操作类**任务，产出可度量性天然弱。我们必须把"**操作的安全性与正确性**"做成可度量对象（对抗通过率、注入阻断率、误拒率、任务成功率）。

**② 技术栈必须有"一眼看得懂的前沿标签"。**
获奖作品的技术描述里全是硬名词：**多智能体协同、知识图谱、图机器学习、联邦学习、可信推理、幻觉筛除**。
→ **启示**：这是本项目**目前最大的短板**（详见第六节）。

**③ "幻觉"被反复点名——而我们已经做了却没讲。**
2025 冠军明确写"**幻觉筛除**"；同期 AFAC2024 金融智能大赛企业组一等奖（深擎科技乾坤圈 Agent 平台）的核心卖点也是"**金融领域大模型幻觉控制**"。
→ **启示**：我们的"事实零生成 + 算子白名单 + 出处双校验"在**技术上更强**（他们是缓解，我们是结构性消灭），但**没有量化、没有对标、没有写进对外材料**。属"有货没讲"。

**④ 落地证据是分水岭。**
《灵操盘》拿冠军最硬的一句不是技术描述，而是：**已在深圳希施玛数据、方舟云数两家企业部署**、**为深圳国投证券提供每日 A 股分析与热点挖掘**、**获企业"具备良好前景与推广价值"评价**。对比三等奖《FinAgent》，技术同样漂亮，但落地叙事只有"依托微众银行用户数据"。
→ **启示**：本项目目前**零外部验证**。25 天内拿不到企业背书，就必须把"**可验证性**"做到极致（可复现、可自动评测、有第三方能跑的对抗集），**用"可验证"替代"已部署"**。

**⑤ "普惠"是主办方的价值取向，必须写进叙事。**
微众银行的使命是"让金融普惠大众"；冠军作品定位"**普惠量化**"；FinAgent 定位个性化理财。而我们的对外材料里**几乎没出现"普惠"**。
→ **启示**：本项目的普惠叙事其实天然成立——"让不熟悉 App 操作的人也能靠一句话安全地用上银行业务"。要把它**明写出来**。
→ **落到行动**：第七节「策略线」③ 的"价值创造"段。

**⑥ 决赛是"48 小时现场黑客松 + 路演"，不是交完作业就完事。**
→ **启示**：① 架构必须能被 4 人在两天内看懂并现场修改；② 演示必须**当场看得懂**（这是当前最弱的一环）；③ 可能存在"自动评测"这一轨，需提前对齐接口。

### 3.3 评委实际怎么打分

**（a）赛事灵魂人物杨强（微众首席 AI 顾问）在 2025 颁奖礼的原话——基本就是评分纲领：**
> "金融科技的下一程不再是技术的单点突破，而是**技术创新 + 场景落地 + 价值创造**的协同演进。"

**（b）2023 技术公开课披露的评审口径**（AI 赛道通用）：
- **创新性**：创意亮点、用新思维解决现有问题、有望开拓新产业模式
- **商业价值**：场景与用户有代表性、贴合真实痛点、有社会价值、合法合规、成长性与可持续性、**值得规模化推广**
  → 其中"**成长性与可持续性 / 值得规模化推广**"要求一条**可复制路径**（本项目天然成立：安全内核渠道无关、不依赖特定银行的改造）；落到行动见第七节「策略线」③ 的"价值创造"段。
- **完整性及可行性**：含**竞品分析**

**（c）同类赛事的分项权重（参照，非本赛事）**：某国际大学生 FinTech 创新大赛公开权重为——技术 25 分 · **创新点及实施方案 30 分** · **项目价值及落地性 20 分** · 行业与市场 10 分 · 数据严谨性 5 分 · 团队 5 分 · 财务 5 分。**创新 + 落地合计 50 分。**

## 四、官方点名的两个参考产品：事实与对比

> **赛题背景原文**："传统手机银行的操作路径长、功能入口深，用户完成一笔转账平均需要 **3 步以上**操作"；
> 要求"在严格的安全框架内完成银行业务操作（**可参考 OpenClaw 等开源智能体项目**）"；
> "**行业对标：参考 Revolut AIR**。鼓励参赛团队探索**更深入的场景覆盖与更流畅的交互体验**"。
>
> 这说明评审看的不只是"能不能做"，还有**"入口是否更短、交互是否更顺、覆盖是否更深"**。
>
> **本节只提供"事实与对比"**；由此得出的改进动作已统一并入**第七节「改进方向」**，不在此重复。

### 4.1 两个参考产品是什么（事实）

**Revolut AIR（AI by Revolut）**
- Revolut（英国持牌银行）于 **2026-04-09** 正式发布，当月开始向**英国 1300 万客户**滚动开放；
  入口为 **App 内下滑即唤起**，或 `Profile → Chats → AIR`。
- 能力：消费洞察与预算（"我的钱花哪去了"）、投资查询（"英伟达股价多少""今年我的投资收益多少"）、
  订阅管理（暂停定期扣款）、**旅行**（实时汇率、"给我买一个 3GB eSIM"）、**卡片控制**（"冻结我的卡""我要一张一次性虚拟卡"）。
- **安全设计三条（官方原话）**：
  ① **零数据留存**——个人数据不被第三方 AI 伙伴存储、不用于训练；
  ② **生物识别**——**AIR 未经你的生物识别批准，不能执行敏感操作**；
  ③ **完全透明**——AIR 只访问你本来就能看到的数据（交易、投资、卡片）。
- 定位原话（CX & AI 产品总经理 Julia Ponomareva）："在无数标签页和菜单里找功能的时代结束了……
  它是一个副驾……而**客户始终牢牢坐在驾驶位上**。"
- 合规姿态：明文声明"不构成投资建议"；答不上来会自动转人工客服。

**OpenClaw**
- 开源个人 AI 助理，**2025 年 11 月以 "Clawdbot" 之名发布**，后先后改名 Moltbot、OpenClaw；
  作者 Peter Steinberger（奥地利）。MIT 许可，Node.js 构建，自托管。
- 架构特征：**常驻的 Gateway 是控制面，"助手"才是产品**；连接 **20+ 消息渠道**
  （WhatsApp / Telegram / Discord / Slack / Signal / iMessage / Google Chat / WebChat / QQ Bot 等），
  **跨渠道共享上下文**。
- 能力特征：**100+ 预置技能（Skills）**，可用 Markdown 或 TypeScript 自写技能、有社区技能库，
  **甚至可以让它自己给自己写技能**；**持久记忆**（"越用越懂你"）；**24/7 主动智能**
  （后台任务、cron、心跳、webhook —— 不等你问就主动做事）；**多智能体协调**
  （subagents / swarm / ACP agents / 多智能体沙箱）；多模型可切换与故障转移；
  文件读写、终端命令、浏览器控制、代码执行。
- ⚠️ **事实可靠性提示**：星标数在不同第三方页面口径不一（23 万+ ~ 24.7 万，均为**推广/聚合页**而非官方仓库），
  本文件仅采信"它为 2025 年末至今增长最快的开源智能体项目之一"这一方向性事实，**不引用具体星标数字**。
  官方文档站点为 `docs.openclaw.ai`。

> **一条关键判断**：OpenClaw 的权限模型（文件 / 终端 / 浏览器 / 自写技能）**与银行场景根本冲突**。
> 赛题说"可参考 OpenClaw"，指的是参考它的**Agent 架构与交互形态**，而不是它的权限模型。
> **在材料里主动指出这一点，本身就是一次"我们懂安全边界"的表态。**

### 4.2 三方对比

| 维度 | Revolut AIR（商业对标） | OpenClaw（开源参考） | 本项目 | 判定 |
|---|---|---|---|---|
| 定位 | 持牌银行 App 内的 AI 助手 | 个人通用助理，自托管 | 一句话操作**银行**业务的智能体 | ✅ 与赛题一致 |
| **交互入口** | **App 内下滑即唤起 + 单一聊天框** | 20+ 消息渠道，像给同事发消息 | Web 单页：输入框 + 7 个按钮 + 表单；**APP 未做** | ❌ **最大的体验差距** |
| 场景覆盖 | 消费洞察 / 投资 / 订阅 / 旅行 / 卡片 | 邮件 / 日历 / 文件 / 浏览器 / API / 表单 | **官方六场景全覆盖**（24 个动作） | ✅ **强于两者** |
| **主动服务** | 有洞察推送 | **强项**：24/7 后台任务 / cron / 心跳 / webhook | **无**，纯被动响应 | ❌ **语义偏差** |
| 记忆与个性化 | 基于 App 内数据（消费 / 持仓 / 地址） | **强项**：持久记忆 | **无**（会话在进程内内存，重启即丢） | ❌ 短板 |
| 多渠道 | 仅 App 内 | **强项**：20+ 渠道 + 跨渠道上下文 | Web 已实现；IM 为最小适配器；**无跨渠道上下文** | ❌ 赛题明文要求 APP、IM |
| 技能扩展 | 未公开 | **强项**：100+ 技能，可自写、社区库 | 24 个动作写死 | ⚠️ 借鉴"技能"**产品抽象**，**不借鉴**"可自写" |
| 多智能体 | 未公开 | 有 subagents / swarm | **无**（单次 LLM 调用） | ❌ 印证第七节刀刃① |
| 多模型 | 未公开 | 数十家模型 + 故障转移 | 单一模型 + 规则模板降级 | ⚠️ 可选增强 |
| **敏感操作确认** | **生物识别**（App 侧） | 未强调 | 三色分级 + **服务端一次性验证码** | ⚠️ 我们**可验证性更强**（服务端挑战 + 留痕），对方**体验更好** |
| 数据边界 | 只访问你本来能看到的数据 | 全系统访问 | 只读网关 + 动作白名单 | ✅ **与银行场景更匹配** |
| 零数据留存 | **对外明确承诺** | 自托管（数据不出本机） | 无对外承诺条款 | ❌ 补一句成本极低 |
| 可审计 | 交互会被记录 | 有日志 | **强项**：哈希链审计 + 完整决策链 | ✅ **强于两者** |
| 幻觉治理 | 明示"信息可能不准确"免责 | 无特别机制 | **强项**：事实零生成（结构性） | ✅ **强于两者** |
| 兜底 | 答不了自动转人工客服 | 无 | 转人工接管包（意图 / 计划 / 规则 / 审计 ID） | ✅ 对齐 |

### 4.3 一条可用于答辩的定位结论（**判断**）

> **"Revolut AIR 让银行 App 更好用；我们让银行 App 敢让 AI 自己动手。"**

AIR 是**持牌银行在自己 App 内的闭环助手**（体验优先，安全靠 App 侧生物识别）；
本项目的价值在于把"**安全框架**"做成**可复用、可审计、可被第三方对抗验证的内核**——
这正好对应赛题三项硬要求中权重最高的那部分，也是"价值创造"最容易立住的地方。

## 五、公开基准：可对标的横向标尺

搜"银行智能体评测"时发现的公开基准，**全部对口本赛题**，其中两个结论几乎是给本方案架构的实证背书。

| 基准 | 方法 | 已发布结果 | 对我们的意义 |
|---|---|---|---|
| **APort Vault**<br />2026-09 | 回放一次公开 CTF 中人类对真实支付智能体发起的 **4,371 次攻击**；覆盖 8 家实验室的 14 个模型 × 5 种策略配置；一条轨迹启用"确定性事前检查"、一条不启用；共 225,964 次评估 | **加确定性事前检查后，向未授权收款方的违规划转由 140 次降为 0 次**（76,842 → 69,297 次评估）；**同期正常执行了 25,370 笔合法支付**，策略层 25,640 次转账调用中仅否决 187 次（其中 148 次因收款方不在允许名单） | **这就是"无裁决不执行"的实证**：安全不等于拒绝一切。可直接作为答辩金句与对比锚点 |
| **FraudBench**<br />2026-08 | 基于 τ²-bench 双控框架与 τ-Knowledge 银行环境；150 个对抗场景（公开冻结集 107）；690+ 条内部政策语料；评分含动作 / 状态 / 泄露 / 处置，且**依赖完整对话历史** | **四个 agent 的攻击安全性仅 49%–65%**；最常见弱点为资金转移类与内部人欺诈 | 现成的横向标尺：本方案若能做到**显著高于 65%**，即构成"技术创新"的硬证据 |
| **τ-Knowledge / τ-Banking**<br />2026-03 | 银行域，约 **700 条政策文档**的知识库；任务成功依赖"检索 + 应用政策" | 发现 agent 的主要失误之一是"**过度相信用户的断言**"（约 4%） | 提示本项目缺一个**政策知识库**（现为硬编码规则）；"不过度相信用户"正是我们的控制槽零信任 |
| **FinToolBench**<br />2026-03 | **760 个可执行金融工具** + 295 条查询；评估维度含时新性、**意图克制（intent restraint）**、监管域对齐 | 指出通用基准"分不清'调用成功'与'该不该调用'" | "**意图克制**"与本项目"绿色只允许纯查询"**是同一条原理**——我们早就在做，只是没命名、没宣传 |
| 参考：CNFinBench | 中文金融大模型与智能体评测；智能体维度含目标分解 / 路径规划 / 工具调用 / 意图识别 / 记忆 / 多智能体协作 | 公开评测体系 | 可作为中文语境下的对标清单 |
| 参考：FrontierFinance | 投资研究工作流，220 条专家查询 + 11,543 条评分细则 | 最强系统仅 56.0% | 说明"金融 Agent 普遍很弱"，我们有空间 |

### 5.1 可直接引用的三条结论

1. **"策略层把违规划转从 140 次压到 0 次，同时 25,370 笔合法支付照常执行"**（APort Vault）——回答"你们的安全机制会不会把业务全挡住"。
2. **"现有银行 Agent 对抗攻击安全性仅 49%–65%"**（FraudBench）——回答"你们比现有方案强在哪"。
3. **"评测必须区分'调用成功'与'该不该调用'"**（FinToolBench）——回答"为什么纯查询自动执行、写操作必须过门"。

### 5.2 怎么用（本轮最高优先级）

**把我们自己的数字，放到同一张表上。** 这是 25 天里唯一能让"价值与落地"从 0 分变正分的路径。
具体动作见**第七节「证据线」**。

### 6.2 结论修正（**判断**）

**不是"整体水平不够"，而是"分数花在了评委看不见的地方"。**

## 七、改进方向：三条刀刃 + 一条证据线 + 八项补强 + 一条策略线

**总原则：不铺新功能。** 从 10-08 到 11-02 只做三件事——**给 AI 补深度、给价值补证据、给全部补叙事**。

### 刀刃 ①：多智能体安全协同（补"AI 标签"，唯一要新增的技术）

**现状**：一次 LLM 调用出意图 → 确定性管道执行（单角色）。
**目标**：三个角色**互相制衡**——

- **规划者（Planner）**：拆意图、补槽位、组装 DAG 计划
- **审查者（Reviewer）**：独立复核计划是否有越权动作、参数是否被未受信文本污染
- **风险官（Risk Officer）**：独立判定级别与是否转人工

**关键设计不变式（必须守住）**：**执行权不在任何 Agent 手里**。三者都只能提交"计划"，由独立的执行门放行。这样"多智能体"不会削弱现有的三条硬约束。

**为什么值钱**：把"安全"从**写死的规则**升级为"**多个 Agent 的对抗性协作**"；既是 AI 前沿标签，又比"单一大模型 + 提示词约束"可信度高一个量级；而且**天然可演示**（三个角色依次亮灯，每层拦下什么一目了然），直接治"决赛路演看不懂"的病。

> **外部印证**：官方点名的开源参考 **OpenClaw** 已提供 subagents / swarm 等多智能体协调能力（见 4.1）；
> 往届冠军《灵操盘》《FinAgent》的技术标签也都是"多智能体协同"。**这条不是我们自说自话。**

### 刀刃 ②：事实零生成（把已有的硬货变成卖点）

已在实现中，要补的是**表达与证据**：

- **形式化说明**：为什么"结构性消灭幻觉"比"提示词让模型别编"更可靠——一句话：**前者让模型没有能力编，后者只是让它不愿意编**。
- **可反驳性演示**：任何输出都能追到记录号，且可现场回读校验。

### 刀刃 ③：个体金融画像驱动的主动服务（补"价值创造"）

**现状**：用户说一句，系统做一件。
**目标**：**主动巡检**——从流水识别订阅扣费（已有雏形）、扫描异常大额、提示预算偏离；用户问"最近有什么我没注意到的吗"即主动汇报。

**为什么值钱**：往届冠军全部有"从数据里挖价值"的成分（用户画像、知识图谱）；这一块是**最容易讲"普惠"故事**的，且实现成本低。

> **外部印证（重要：这条其实是对赛题的语义修正）**：官方六大场景里的"**异常交易识别**"与"**续费提醒**"，
> 语义上**本来就是主动的**，我们却都做成了"你问它才答"。
> 商业对标 **Revolut AIR** 有主动的消费洞察推送；开源参考 **OpenClaw** 更是把"**24/7 主动智能**"
> （后台任务 / cron / 心跳 / webhook，**不等你问就主动做事**）作为核心卖点。
> **所以这不是"锦上添花的功能"，而是我们此前对赛题的理解偏差。**

### 证据线（**最紧急**，因为它把 50 分从 0 变正数）

| 动作 | 产出 |
|---|---|
| 把现有对抗库扩成**可发布数据集**（注入 / 越权诱导 / 多轮诱导 / 金额绕过） | 一个第三方能跑的对抗集 |
| 跑出**四个业务指标** | ① 注入与越权诱导阻断率 ② **误拒率**（最关键，证明"安全不等于拒绝一切"）③ 六场景任务成功率 ④ 资金数字可回溯率 |
| **对标公开基准** | 把我们的数字与 FraudBench 的 49%–65%、APort Vault 的"140→0"放进同一张表（第五节已备好标尺） |
| 一键复现脚本 + 结果表 | "第三方可以自己跑一遍"——**没有企业背书时的替代品** |

> **判断**：这四条做完，"价值与落地"从**空白**变成**可验证**。这是 25 天内唯一能拿到落地性分数的路径。

### 刀刃之外的七项补强（来自第四节的两个参考产品）

> 以下是**体验与叙事层**的补强，不含新技术。**安全层一律不动**（白名单、执行门、控制槽零信任）。

**① 入口必须极简——这是赛题痛点，也是我们自己的痛点。**
赛题抱怨"操作路径长、功能入口深（转账要 3 步以上）"，而本项目当前界面是"输入框 + **7 个按钮** + 表单"，
**我们自己就长成了被批评的样子**。AIR 的做法是"下滑即唤起、一个聊天框说一句话"。
→ **行动**：首屏只留一个输入框 + 一个主按钮，其余按阶段出现（设计仓 `product-web.html` / `product-app.html` 已给出方向）。

**② 敏感操作确认：我们更强，但要补齐"体验面"。**
AIR 用生物识别，我们用服务端一次性验证码。我们的方案**渠道无关、可留痕、可被审计**（AIR 的生物识别在银行侧无法留下"谁在什么规则下批准"的机器可读证据）；但 **App 侧的生物识别体验更顺**。
→ **行动**：材料中把"渠道无关的强验证"讲成优势，同时在**架构上留出 App 侧生物识别的接口位**（设计层面即可，不必真做）。

**③ 补一条"数据边界"对外声明。**
AIR 把"零数据留存""只访问你能看到的数据"写成了**对外承诺**。本项目技术上完全做得到（只读网关、无外呼），
但**一句话都没说过**。这与"监管要证据"的叙事直接相关。
→ **行动**：在 README 与安全自评中补一节数据处理边界声明。成本极低，收益直接。

**④ 借鉴"技能（Skill）"的产品化抽象，但不借鉴"可自写"。**
OpenClaw 把能力组织成"技能"，用户看得懂、能组合。我们的 24 个动作是**机器视角的白名单**，
用户看不到、也说不清"我能让它干什么"。
→ **行动**：把 24 个动作**包装成用户可读的"技能卡"**（场景入口卡即雏形），
**但白名单与执行门一律不变**——只改叙事层，不改安全层。

**⑤ 记忆与跨渠道上下文。**
OpenClaw 的"持久记忆"与"跨渠道共享上下文"是体验分水岭。我们连会话都是进程内内存、重启即丢。
→ **行动**：会话持久化（低成本）；跨渠道上下文（成本高，25 天内可只做"同一后端会话、多渠道接入"的说明）。

**⑥ 多模型与降级策略，可参考其"故障转移"思路。**
OpenClaw 支持数十家模型并做故障转移；我们目前是单一模型 + 规则模板降级。
我们的降级通道**更可靠**（确定性、不依赖外部服务），但**可在材料中把"双通道"讲成设计优势**而非临时兜底。

**⑦ 把开源参考项目当"安全反面教材"，主动对比反而加分。**
建议在材料中主动写明："我们不采用 OpenClaw 式的全系统权限（文件 / 终端 / 浏览器 / 自写技能），
因为银行场景下'**能力越强 = 攻击面越大**'。"
——**主动划出自己的边界，比堆功能更能体现安全设计能力。**

### 补强 ⑧：把"已经做了但没命名"的能力变成对标标签（**零开发成本**）

前面几节的表里散落着**四条已实现、却没被命名**的能力。它们与刀刃②同性质——**不需要新技术，只需要命名 + 对标**，是本轮投入产出比最高的一档。

| 能力（本项目已有） | 外部标杆（可直接对标） | 怎么讲 |
|---|---|---|
| **意图克制**：绿色只允许纯查询，写操作一律过执行门 | **FinToolBench** 把它作为**独立评估维度**（intent restraint），并指出通用基准"分不清'调用成功'与'该不该调用'" | 把"绿色只允许纯查询"直接命名为**意图克制**，明示与 FinToolBench 同源（见 5.1 ③） |
| **不过度相信用户断言**：控制槽零信任，用户口述值进不了控制槽 | **τ-Knowledge** 发现"过度相信用户的断言"是 agent 主要失误之一（约 4%） | 我们的控制槽零信任**结构上不可能**过度相信用户（见第五节 τ-Knowledge 行） |
| **可解释性输出**：每个结论都能回读依据（决策链 / 命中规则 / 数值出处） | **2025 赛题明文要求过这一条**（见 3.1）；2026 三项硬要求虽未单列，评审惯性仍在 | 对**盲审**这一轨尤其吃分——评委不跑代码，只能读材料 |
| **可审计**：哈希链审计 + 完整决策链 | 见 4.2：**对 AIR 与 OpenClaw 都占优**（AIR 只说"交互会被记录"，OpenClaw 只有普通日志） | 补进方案对比表，并补一条量化（结论可追到记录号的比例） |

→ **行动**：在技术文档与答辩材料里，把这四个名字**当标签用**（中文首次出现处带上英文原词：intent restraint / policy-grounded / explainability / auditability）。**不改任何实现、不动安全层。**

> **判断**：这一条与刀刃②合计，把"有货没讲"从 **1 项补到 4 项**，且**零开发成本**——
> 是 25 天里除证据线外唯一"当天就能得分"的动作。

### 策略线：不依赖技术的三条行动

**① 「最佳创意奖」是一条独立的、门槛最低的获奖通道。**

第一节的奖金构成写着：单赛道 25 万 = 一等 10 / 二等 8 / 三等 5 / **最佳创意 2 万**。
四条通道里，**"最佳创意"比的是创意而非完整度**，需要的材料侧重完全不同——一个记忆点 + 一句话讲清 + 现场一个"哇"时刻。

→ **行动**：单独准备一套预案，**不复用**完整性叙事的材料：
- **一句话创意主张**（可直接用 4.3 的定位句）：
  "Revolut AIR 让银行 App 更好用；我们让银行 App **敢让 AI 自己动手**。"
- **一个可现场复现的对抗演示**：注入攻击被拦下的完整过程，前因后果 30 秒讲完；
- **一句"为什么此前没人这么做"**：既有的银行 Agent 都把安全当成**提示词约束**，而不是**执行层的结构性约束**。

**② 「双轨评审」意味着两套受众，材料必须分两条线组织。**

评审是"自动评测 + 专家盲审"双轨（见第一节）。关键含义：**盲审评委不会跑你的代码，只能读材料。**

| 轨 | 受众 | 该给什么 |
|---|---|---|
| **自动评测轨** | 脚本 | **可跑的东西**：对抗集 / 复现脚本 / 结果表（见上「证据线」） |
| **盲审轨** | 人 | **可读的东西**：架构图 / 算法说明 / 安全自评 / 作品简介——且**必须不依赖运行就能自证** |

→ **行动**：这正是 6.1「材料完整度」被判为"❌ 半空"的真正原因——它扣的是**另一条轨的分**。
因此**材料补齐的优先级应与证据线同级**，而不是"等代码做完再说"。

**③ 用评委主席的三句话当材料骨架。**

3.3(a) 引了杨强的原话："金融科技的下一程不再是技术的单点突破，而是**技术创新 + 场景落地 + 价值创造**的协同演进。"
——这就是评分纲领。**直接拿它当答辩 PPT 与作品简介的三段结构**（8.2 已安排"路演脚本"但没指定结构，用它就是白捡的分）。

→ **行动**：固定三段——
**技术创新**（刀刃① + 补强⑧ 的四个标签）→ **场景落地**（六场景 + 渠道 + 主动服务）→ **价值创造**（普惠 + 可复现证据 + 可复制路径）。

### 8.3 明确不做（保住 25 天）

- **不新增业务动作**：24 个动作已足够覆盖官方六场景，继续加只稀释注意力。
- **不重写架构**：现有分层与三条硬约束是本项目最大资产，刀刃①必须**嫁接**而非**替换**。
- **不接真实第三方平台**：IM 只做到"可说明的最小实现"，把时间给证据线。
- **不开放"AI 自写技能"**：OpenClaw 的这条能力在银行场景下不可用（见七项补强⑦）。
- **不投入知识库 / RAG**：官方三项硬要求与六大场景**都是操作类**，没有一条指向文档问答；τ-Knowledge 提示的"政策知识库"缺口（见第五节）**推迟到 10.28 答疑之后**再定，应急口径见 8.4 对应风险行。
- **不美化材料措辞**：与项目既有"不夸大"纪律一致——**没做的就标目标态**。

### 8.4 风险与诚实边界

| 风险 | 应对 |
|---|---|
| 官方自动评测有未公开的接口要求 | 10.28 必须问清；同时把"可复现"做扎实，使接口形式可快速适配 |
| 25 天内跑不出"显著优于 65%"的数字 | **如实披露**，并说明差距来源——比编数字安全得多 |
| 企业背书拿不到 | 用"可复现证据 + 可复制路径"替代，**不虚构部署案例** |
| 刀刃① 引入新 Agent 反而削弱安全 | 守住"执行权不在 Agent 手里"这一不变式，并补回归测试 |
| 补强与策略线挤占关键路径 | 只做**叙事与界面层**，凡涉及安全层的一律不改；优先级低于刀刃①与证据线 |
| **10.28 答疑确认"考察知识库 / RAG"** | **应急预案（不提前投入）**：不新建向量库、不改执行路径。最小应对是把既有的**规则表声明为知识库的可读投影**（"政策 → 规则码 → 动作"三级映射已有），并补一段"检索 → 应用政策 → 命中规则"的说明与示例即可回答"有没有知识库" |
| 补强⑧ 的四个标签被当成"贴标签" | 每个标签都必须**指到实现**（意图克制 → 绿色只允许纯查询 / 不过度相信断言 → 控制槽零信任 / 可解释性 → 决策链 / 可审计 → 哈希链）。**只讲结论不给代码位置的标签一律不写** |
