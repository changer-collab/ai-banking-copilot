### 第 2 页 · 问题

- **任务**：40 秒把问题从「用户懒」改写成「银行不敢」。
- **版式**：左侧 35% 大数字；右侧 65% 三行失败模式（每行：编号圆 + 红字失败模式 + 灰字答案）；底部一条横贯转折句。
- **上屏逐字**：
  - 页眉：`02 / 问题`
  - 标题（23pt）：**门槛不是「用户懒」，是银行不敢把操作权交给一个会编、会被诱导、会越权的模型**
  - 大数字（128pt，强调蓝）：**7**；旁边 30pt：**步**
  - 数字下说明（11pt，灰）：`手机银行完成一笔转账的` / `实际点击步数（我方实测）` / `scripts/measure_interaction.py`
  - 三行：
    1. **会编造** → `事实零生成，数值只从网关取` / `模型不生成任何金额、余额、回执`
    2. **会被诱导** → `策略层按请求结构裁决，不读模型的话` / `注入命中直接转人工，不进自动执行`
    3. **会越权** → `权限分级 + 计划级净效应，引擎在 LLM 之外` / `执行权不在任何 Agent 手里`
  - 转折条（24pt，白字，深蓝底，左侧 6px 蓝色竖条）：**7 步变 1 句是效率问题；真正拦住银行的，是敢不敢把操作权交出去。**
  - 页脚（7.5pt）：`口径：现有手机银行页面实际点击路径；不含生物识别与后台处理。不替赛题「3 步以上」背书。`
- **口播（40s）**：
  1. 「先看一个数：我们自己量的，一笔转账 7 步。」
  2. 「但真正拦住银行的不是 7 步，是三个失败模式：会编、会被诱导、会越权。」
  3. 「这三个问题靠提示词解决不了，只能靠模型之外的确定性层。」
  4. 「所以门槛不是用户懒，是银行不敢。」
- **证据**：`scripts/measure_interaction.py`；`docs/RESULTS.md` §5。
- **预期追问**：
  - Q：7 步怎么数的？→ A：从打开 App 到拿到回执，含登录、选收款人、填金额、确认、验证、结果；脚本可复跑。
  - Q：为什么不用赛题的 3 步？→ A：官方只给概述、没给测量方法；我们用自己可复现的 7 步，不替官方数据背书。
- **不做**：不复述 Agent 行业大势；不把三个失败模式展开成技术讲座。

## 七、统稿纪律

1. **标题即结论**：一句可判断真假的话；禁止「系统架构」「场景介绍」「总结」。
2. **一页 ≤3 个上屏要素**；第 4 个进备注。
3. **不念 PPT**：页面是证据，嘴里讲因果。
4. **每个机制必须有可见证据**：指不到一处的删掉。
5. **不宣称未实现**：不出现「短信 / 人脸 / U 盾已接入」「真实盲测」「生产可用」「已超越 AIR」；飞书只说「真回调 + 演练兜底」；净值必须带「模拟数据」。
6. **数字必须有命令**：每个百分比指到 `docs/RESULTS.md` 的复跑命令。
7. **盲审可读**：任一页单独截屏给没听过讲的人看，应能看懂。
8. **能力子集正面讲**：25 项点名 25 有 / 0 半有 / 0 无；28 个动作；两条保留主动说。
9. **生活链路只讲 7 类形状**：L1–L7 是形状不是「任意生活事件都懂」；到期预约 ≠ 已执行。
10. **渠道分支讲清楚**：PWA = 官方「APP」形态；飞书 = 真回调；到期推送默认关闭。
11. **附录不上台**：A1–A5 只在答问时翻；主 deck 仍 12 页、9:30。
12. **11-02 新增口径**：卡片写「临时冻结 / 正式挂失 / 补卡」；理财写「份额赎回 / 适当性弹窗」；账单写「统一消费口径」；代扣写「协议视图 + 本行侧解约」；转账写「演示开户行 + 未核验」。
