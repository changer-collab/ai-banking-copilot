场景页新增三块可视化（都在 `#wealth-viz`，**CSS 手写，无第三方库**）：

### 1.1 风险等级阶梯（新增）

- 位置：理财场景页第一张卡，`#wealth-viz .wealth-ladder`。
- 实测：5 格 `R1 R2 R3 R4 R5`，**R3 高亮并带「当前」标记**（`aria-current="true"`），下方一行
  `当前 R3 · 有效期至 2027-09-01`；无有效等级时整条写「尚未取得有效等级：先完成测评，产品才按等级判定。」

  前端只做 R1→R5 的**顺序映射**（`RISK_SCALE`），**不算等级、不算分数**。

### 1.2 持仓占比（新增）

- 位置：`#wealth-viz .wealth-share`，每行「名称 / 条形 / 百分比 / 金额」。
- 实测（8000）：

  | 产品 | 占比 | 金额 |
  |---|---|---|
  | 稳利债券 A | 75.0% | 3000.00 元 |
  | 活期理财篮子 | 25.0% | 1000.00 元 |

  块头小字 `合计 4000.00 元`。
- **时点口径（与答辩素材的 88.9% / 11.1% 不矛盾）**：本表采集于当天更早一轮，当时库内合计 4,000.00 元；
  之后 §7.1 的 S6-4 对账用例在**同一个演示库**又申购了 1,000.00 元，**当前库合计 9,000.00 元**
  （稳利债券 A 8,000.00 → 88.9% / 活期理财篮子 1,000.00 → 11.1%），答辩素材截图取的是这一轮。
  两处差额只来自那笔留证操作，**占比算法未变**（本项 / 接口返回的合计，前端不估数）。
- 数据来源：`holdings[].name` / `holdings[].amount_yuan`；占比 = 本项 / 合计，**合计也来自接口**，
  没有任何前端估数。没有持仓时写「当前没有持仓，暂无可计算的占比。」（不用 0% 假撑）。

### 1.3 收益（新增，**无净值就标「未知」**）

- 实测：大字 `未知`，说明 `全部 2 笔持仓均无净值数据，收益标「未知」，不推算盈亏。`
- 数据来源：`holdings[].current_income`，其值就是服务端常量

  前端只判断「含不含『未知』」，**不补零、不按份额×净值倒推盈亏**。

```
                  （`.venv` 已 editable 安装，不需要 PYTHONPATH）
```

> **为什么必须写明解释器**：同一台机器、同一份代码，全局 python 装的是 **mypy 1.15.0**，
> 会在 `policy/verification.py:499` 报一条
> `Returning Any from function declared to return "_T"  [no-any-return]`；
> 仓库 `.venv` 的 **mypy 2.4.0** 判定为 `Success`。
> 这是 **mypy 版本差异**（该文件 `__init__` 的形参写成 `VerificationAttemptStateStore | Any | None`，
> 1.15 会把返回值收敛成 `Any`，2.4 不会），**与操作系统、Python 安装、缓存都无关**，
> 也已用最小复现验证：不含任何项目依赖的 40 行文件在 1.15 下报同样的错。
> 结论：**门禁一律用 `.venv` 跑**；本机全局 python 这一档（mypy 1.15.0）会看见这条，用 `.venv` 不会。
> 要彻底消除这条版本敏感报错，需把该形参收成 `VerificationAttemptStateStore | None`（或显式 `cast`），
> 属 `policy/**`，见 §5 第 9 条。
