## S0 场景卡

官网赛题「03 理财操作」的典型能力示例原文（2026-10-26 直读 <https://fintechathon.g-ican.com/#/> 赛题说明），照录为：**「产品推荐与对比；风险评估；一键申购 / 赎回」**。下表逐条照抄，不改写。

| # | 赛题原文（照抄，不改写） | 现状 | 说明 |
|---|---|---|---|
| 1 | 产品推荐与对比 | 已有 | `wealth.list` 的推荐模式先过测评闸门，再由**服务端硬筛选**只保留「产品等级 ≤ 测评等级」的候选（`scenarios/wealth.py` 的 `recommend_products`）；展示只陈述名称 / 风险等级 / 期限 / 起购，流动性、费用、潜在亏损一律标「未知（产品数据未提供）」。限制：仅 4 只内置演示产品，并标注「非真实在售产品」。 |
| 2 | 风险评估 | 半有 | 有测评状态机（未测评 / 过期 / 等级不匹配 → 硬拒绝，`assess_suitability`）、`risk_assessments` 表、`GET/POST /api/risk-assessment`、演示 seed（u_demo = R3，来源 `seed`，**非真实测评**）。缺：没有「一句话能答」的测评题库；前端没有测评录入入口（`web/assets/app.js` 搜不到 risk / 测评 / assessment）；对话侧没有「我要做风险测评」的意图。 |
| 3 | 一键申购 / 赎回 | 半有 | 申购已强制红色 + 服务端一次性强验证；赎回黄色计划卡确认链路可用。但「一键」不成立：申购要 account / product / amount 三个控制槽 + 一次强验证；`product` 槽只认受信任选择、不从文本解析，未选时默认 `wp_cash`；赎回没有持仓表与持仓校验。 |

「一键申购 / 赎回」两半的拆解核对（拆开只是为了能分别验收，不改原意）：

| # | 拆解项 | 现状 | 说明 |
|---|---|---|---|
| 3a | 一键**申购** | 半有 | 红色链路完整：适当性闸门 → `OFFICIAL_RED_ACTIONS` 强制 ≥ 红（不因金额小降黄）→ 红卡 → 挑战 → 确认 → 回执。缺口：三槽 + 强验证，不是一次点击；产品名说在句子里也不会被解析。 |
| 3b | 一键**赎回** | 半有 | 赎回是流入型 ⇒ 金额档不适用 ⇒ 恒黄（`STATE_CHANGE_SMALL`），黄卡确认即可执行。缺口：无持仓查询 / 校验；网关对赎回**也**校验起购金额（`gateway/core_bank.py` 的 `_wealth_flow`），例如赎回 500 元「稳利债券 A」（起购 1000 元）会被拒，语义不对。 |

## S3 门卫申请卡

本场景动作与 [tools/catalog.py](../../../src/ai_banking_copilot/tools/catalog.py#L208-L249) 逐条对齐，共 3 个，一个不漏。

| 动作 | 级别 | 理由（对赛题原文） | 限额 / 强验证方式 | 拒绝话术 |
|---|---|---|---|---|
| `wealth.list` | 绿 | 纯查询：只读产品目录与事实，不改任何状态（`is_pure_query=True`）。推荐 / 对比模式下还要过测评闸门；**拒绝测评不等于升档**，级别仍是绿。 | 无（自动执行）。只陈述风险等级 / 期限 / 起购；收益类字段一律不展示。 | 「我只能列产品事实，不做收益承诺；推荐要先有有效测评，过期就得重测。」 |
| `wealth.subscribe` | 红 | 分工通知的红名单含「理财申购」；代码 `OFFICIAL_RED_ACTIONS` 无条件 ≥ 红，**不因金额小降为黄**（`policy/pdp.py`）。 | 强验证：服务端一次性挑战；TTL 300s；默认 5 次失败锁 300s；退避 0/5/15/60s；挑战绑定 `user_id/session_id/execution_id/card_id/frozen_hash`；验证码只存 HMAC 摘要；确认必须 `card_id + frozen_hash + verification_code + steps` 全一致；红卡不可跳过。 | 「申购必须本人强验证，没通过验证不会扣款；如果测评等级低于产品等级，我直接拒绝，不能靠验证码绕过。」 |
| `wealth.redeem` | 黄 | 分工通知红名单未含赎回；代码口径为流入型（`INFLOW`）⇒ 金额档不适用 ⇒ 恒黄（`STATE_CHANGE_SMALL`）。 | 黄色计划卡确认，无验证码；控制槽 account / product / amount；金额必须为正。 | 「赎回要你确认产品和金额，确认后执行；金额不对我不会动。」 |

不确定栏：

| 事项 | 说明 | 待对齐 |
|---|---|---|
| 大额赎回定级 | 代码恒黄（流入型不适用金额档），但大额赎回对客户同样重大 | 是否按金额或持仓比例升级为红，需组长三色基准表裁决 |
| 「一键」口径 | 申购实际要三槽 + 强验证，不是一次点击 | 对外宣传是否继续写「一键」，需全组统一 |
| 产品槽来源 | `product` 只认受信任 `selected`，不从文本解析；申购未选时默认 `wp_cash` | 用户句中点名产品但未在页面选中时，是追问还是拒绝，S4 定 |
| 赎回持仓 | 无持仓表 / 无持仓校验；网关对赎回也校验起购金额 | 赎回按「持仓」还是按「金额」定义，需裁决 |
| 测评来源展示 | seed 的 R3 是演示数据（`source=seed`），不是真实测评 | 演示时是否强制在页面标注「非真实测评」 |
| 申购可逆性 | `catalog.py` 声明 `wealth.subscribe` `reversible=True`，但 `policy/reversal.py` 只覆盖 `transactions` 流水 | 理财申购能否冲正未核实，**先按不可逆对待**，需组长确认目录声明 |

成绩单口径：

| 指标 | 我这个场景里「算成功」的定义 |
|---|---|
| 用例数 | 本场景计划纳入 7 条（3 主路径 + 3 刁钻 + 1 超范围）；现有评测中理财 9 条（申购 RED ×4、赎回 YELLOW ×2、列表 GREEN ×3）继续保留，不重复计入这 7 条 |

## 附：红色动作强验证样板（附加职责）

这是给全组红色动作抄的标准写法，以 `wealth.subscribe` 为参照实现，步骤全部取自现有代码，不新增机制。

### 八步链路

| 步 | 做什么 | 代码落点 | 不可退让的约束 |
|---|---|---|---|
| 1 | 意图识别 | `planning/llm.py` 的「申购 / 买理财」模板 | 模型只出动作意图，**不产出** `user_id / account_id / product_id / amount_cents` |
| 2 | 补齐控制槽 | `planning/slots.py` + `web/session.py` | 身份只取服务端；`product` 只认受信任选择；缺槽一次只问一个 |
| 3 | 适当性闸门 | `scenarios/wealth.py` 的 `assess_suitability` | 未测评 / 过期 / 等级不匹配 → `SuitabilityError` **硬拒绝**，与金额无关 |
| 4 | PDP 定级 | `policy/pdp.py` 的 `_official_red_modifier` | `OFFICIAL_RED_ACTIONS` 无条件 ≥ 红，modifier **只升不降** |
| 5 | 出红卡 | `web/plan_card.py` 的 `render_plan_card` | `level=RED` ⇒ `requires=(user_confirm, strong_verify)`，由级别单向推导，外部不能自由填写；`card_id = card_{frozen_hash[:12]}_red` |
| 6 | 申请挑战 | `POST /api/verify/request` | 挑战绑定 `user_id / session_id / execution_id / card_id / frozen_hash`；TTL 300s；验证码只存 HMAC 摘要 |
| 7 | 确认 | `POST /api/confirm`（`card_id`、`frozen_hash`、`verification_code`、`steps`） | 任一不一致 → 409；计划过期 → 409；未强验证 → 409；失败 5 次锁 300s，退避 0/5/15/60s |
| 8 | 执行与回执 | PEP → `CoreBank.subscribe_product` | 执行前同事务复核最新事实与余额；成功给真实回执 + 审计；失败如实失败，**绝不谎称已扣款** |

### 四张卡的文案骨架

| 卡 | 何时出现 | 必须写清 | 绝不能写 |
|---|---|---|---|
| 结果卡（绿） | `wealth.list` 等纯查询 | 产品名称、风险等级、期限、起购、数据来源「内置演示数据（非真实在售产品）」、未知项 | 收益率、年化、保本、稳赚 |
| 确认卡（黄） | `wealth.redeem` 等状态变更 | 动作、产品、金额、回款账户、生效方式 | 「已经帮你赎回」（未确认前） |
| 强验证卡（红） | `wealth.subscribe` 等官方红动作 | 动作、产品（含等级）、金额、扣款账户、测评等级与匹配结论、验证码有效时间、一次性说明 | 「验证一下就一定成功」 |
| 失败卡 | 拒绝 / 过期 / 验证失败 / 余额或起购不足 | 失败原因、下一步能做什么、是否已扣款（明确「未扣款」） | 任何成功字样、任何编造的回执号 |

### 失败 / 拒绝矩阵

| 场景 | 用户看到 | 系统行为 |
|---|---|---|
| 未测评 | 「申购前要先做风险测评」 | 不出红卡，不发挑战 |
| 测评过期 | 「测评已过期，请重新测评」 | 不出红卡，不默认等级 |
| R2 买 R4 | 「测评 R2 低于产品 R4，不能申购」 | 硬拒绝；强验证也不能绕过 |
| 验证码错误 | 「验证码不对，还可以再试 N 次」 | 计入失败次数；达 5 次锁 300s |
| 验证码过期 | 「验证已过期，请重新申请」 | 旧挑战不可复用 |
| 计划被改 | 「计划已变化，请重新确认」 | 旧 `frozen_hash` 失效，重新出卡 |
| 用户放弃 | 「已取消，未扣款」 | `/api/reject` 置作废终态，验证码一并失效 |
| 余额不足 / 低于起购 | 「余额不足 / 起购 1000 元」 | 不出执行回执，不扣款 |
