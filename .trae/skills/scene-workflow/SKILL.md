# 场景工作流（一人一摊）

真源文档：`docs/2026-10-26/分工文档-2026-10-26.md`。本技能是它的可执行版本；当天要交什么看 `docs/archive/2026-10-26-d0/交付清单-2026-10-26.md`。

## 安装与生效（组员先看这一段）

1. **工作流是仓库文件，不是插件**：`.trae/rules/project_rules.md`（常驻约束）+ 本文件（八工位展开）随 `git pull` 生效，不需要安装、不需要账号。
2. **Trae 必须打开仓库根目录**（`ai-banking-copilot/`），打开父目录会导致 `.trae/` 扫不到。
3. 拉最新工作分支后，**新开一个对话**，第一句发：`场景：{①–⑥} / 工位：{S0–S7}。按 scene-workflow 走。`
4. 自检：回答第一行应出现 `场景：… / 工位：…`。没有 ⇒ 规则没加载，先检查目录与分支（详见 `docs/2026-10-27/工作流安装指南-2026-10-27.md`）。

## 开场三件事（缺一不可）

1. 确认三要素：**场景**（①–⑥）、**工位**（S0–S7）、**负责人**（尹辰 / 王昌泽 / 高靖雯 / 徐思云 / 林晓研）。
2. 确认本轮允许改的文件范围（见「文件边界」）。
3. 声明本轮**只交付一个工位**的产物，不跨工位跳步。

三要素缺任一项时，先问、不动手。

## 八工位

| 工位 | 你做什么 | 产出 | 出口标准 |
|---|---|---|---|
| **S0 场景卡** | 把赛题表里本场景那一行的「典型能力示例」逐条抄下来，标 `已有 / 半有 / 没有` | D1 | 组长 3 分钟能讲清 |
| **S1 现状地图** | **只读不改**：扫相关文件、已有动作、已有测试、缺口 | 现状地图 | 能指出「哪块是现成的」 |
| **S2 话术** | 列 ≥12 条真人说法（模糊、省略、错别字、反问），定追问策略 | D2 | 逐条在页面上真跑通过 |
| **S3 门卫** | 对照组长三色基准表，给本场景每个动作定绿/黄/红 + 理由 + 限额 + 强验证 + 拒绝话术 | D3 申请卡 | 组长落地后回归通过 |
| **S4 后端** | **先写 D6 七条考题，再实现** | 代码 + 测试 | 全量测试全绿 |
| **S5 前端 + 联调** | 点通结果卡 / 确认卡 / 强验证卡 / 失败卡；验刷新、中断、恢复、接管 | D4 + D5 | 手机宽度点得通 |
| **S6 成绩单（两段）** | **D0 段**：定四个口径 + 写七条考题，不跑分；**D3 段**：后端好了再跑分填数字 | D6 考题 + D7 一行 | 数字与考题对得上、命令可复现 |
| **S7 材料 + 交接** | 1 页 PPT + 30 秒录屏 + 1 句简介 + 3 个问答 | D8 | 组长接收即用 |

时间盒：S0+S1 半天 → S2+S3 半天 → S4 一天 → S5 一天 → S6（D0 定口径 / D3 跑分）+ S7 半天。

## 交付包 D1–D8

| 编号 | 交付物 | 完成标准 |
|---|---|---|
| D1 | 场景卡 1 页 | 赛题原词逐条对得上 |
| D2 | 话术表 ≥12 条 | 每条标注意图、缺哪个槽位、怎么追问 |
| D3 | 门卫规则申请卡 | 动作 × 绿/黄/红 + 限额 + 强验证 + 拒绝话术 |
| D4 | 一条完整前端链路 | 四种卡齐全，失败态也有 |
| D5 | 联调通过 | 真后端、刷新不丢、可中断/恢复/接管 |
| D6 | 考题包 7 条 | 3 主路径 + 3 刁钻（注入 / 越权改控制槽 / 编造）+ 1 超范围 |
| D7 | 成绩单 1 行 | 用例数 / 通过率 / 平均轮次 / 危险动作拦截率 |
| D8 | 材料四件 | 1 页 PPT + 30 秒录屏 + 1 句简介 + 3 问答 |

铁律：**D6 必须在 S4 改代码之前写完**，D7 在 S6 跑出来。禁止事后补数据。

## 文件边界

| 文件 | 谁可改 |
|---|---|
| `tools/catalog.py`、`policy/**`、`planning/kernel.py` | 仅组长（其他人发变更申请卡） |
| `scenarios/*.py`、对应 `tests/` | 本场景负责人 |
| `web/app.py` | 按路由认领，路由前写 `# owner: 高靖雯` |
| `web/assets/app.js` | 按场景块认领，块首写 `// owner: 高靖雯 · 场景①` |
| `README.md`、`docs/*.md` | 分段认领，组长统稿 |
| `eval/data/*.json` | 只加自己场景段内的用例，用场景前缀命名 |

## 各工位的执行要点

### S1 现状地图（只读）

输出四段：相关文件清单 / 已有动作（对照 `tools/catalog.py`）/ 已有测试 / 缺口清单。不改任何文件。

### S2 话术表

先给 20 条候选，人工挑 12 条。每条包含：`用户原话`、`真实意图`、`缺失槽位`、`Agent 应说什么`。
必须覆盖：模糊表达、省略上下文、错别字、反问、跨场景跳转。

### S3 三色分级（对照赛题原文）

- 绿 = 纯查询（余额、流水、账单分析、收益查询）
- 黄 = 小额转账（日累计 ≤1000）、订阅查询/取消、虚拟卡申请
- 红 = 大额转账（日累计 >1000）、密码修改、挂失/解挂、理财申购
拿不准的单独列「不确定」栏，交组长裁决，不自行放宽。

### S4 后端

1. 先把 D6 七条写成测试/评测用例并跑（应当失败）。
2. 再实现，只改本场景 handler 与必要槽位。
3. 收工贴全量测试输出。

### S5 前端 + 联调

四种卡必须都有：结果卡、确认卡、强验证卡、失败卡。逐项验：刷新不丢状态、中断可恢复、可人工接管、失败如实报错（不得前端伪造成功）。

### S6 成绩单（两段，别混）

**D0 段（后端还没好）**：只做两件事——定四个口径（用例数 / 通过率 / 平均对话轮次 / 危险动作拦截率），并把七条考题按「输入 → 期望行为 → 期望结果（可判定）」写出来，**不跑分、不填数字**。

**D3 段（后端已合并）**：跑分填四个数字，并逐条列「输入 → 期望 → 实际 → 是否通过」。数字必须能用 `scripts/run_benchmark.py` 或等价命令复现，并注明采集时间与开关状态（template / llm-strict）。

### S7 材料

一页 PPT 三行：生活话一句（≤25 字）+ 技术注解两行 + 一个数字。录屏 30 秒只演示一条主路径。

## 给 agent 的开场模板

```
你是「{场景名}」的场景负责人助手，当前工位：{S0–S7}。
只允许修改：{本场景文件 + 对应测试}。
禁止修改：tools/catalog.py、policy/ 核心逻辑、planning/kernel.py；确需变更时先输出「变更申请卡」。
本轮只交付该工位的产物，不要顺手改其他工位。
```
